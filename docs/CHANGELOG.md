## 2026-10-06 v0.2.7（新版本 · 真机验收修复 7）

### 调用链按钮的禁用态（真机反馈）
- 「置顶 / 上移」在**最上面**时、**下移**在**最下面**时，**必须灰掉不可用**。
- 根因不是逻辑：三个调用链界面（牛马管理局链、特殊模型链、右侧模型管理链）**早就在边界挂了 `disabled`**，
  但两份 CSS 里**没有任何 `.anNiuXiao:disabled` 规则** ⇒ 浏览器默认的禁用观感被自定义按钮样式盖掉，
  看起来和能用一样，用户以为"按了没反应"。
- 修法：两份 CSS 同时补 `.anNiuXiao/.anNiuGhost/.anNiuGongJu` 的禁用态（透明度 .4 + `cursor: not-allowed` +
  去色 + 去掉悬停高亮）；「启用/禁用」按钮**永不置灰**（禁用了还得能点回来）。
- 门禁 `verify-chain-buttons`（12 项）：既查三处边界判定，也查**真浏览器里算出来的禁用观感**（opacity/cursor/filter）。

## 2026-10-05 v0.2.5（新版本 · 真机验收修复 5）

### 预计完成时间（ETA）：给"是否卡死"再加一根标尺（新功能）
- **要求落地**：模型每次判完"是否卡死"，**都要**给出一个预计完成时间；
  同一轮里多次判断时，提问里带上**它自己之前写的**历次预测（含"超了没、还差多久"）；
  这些数据**写进持久配置文件** `userData/eta.json`；
  一轮任务**连续 3 次**超出模型自己给出的预计完成时间 ⇒ 按异常处理（停下 + 明确警告）。
- **不是"一个时间"**：每条预测都记 相对时长 `etaMs` + **绝对截止时刻** `jieZhiMs`
  （重启后仍能判超时）+ 当时已跑多久 `yiYongMs` + 依据 `genJu` + 来源 `laiYuan`
  （model/history/default）+ 是谁预测的 + 结论回填（命中/超时、实际耗时）。
- **自我完善（越用越准）**：按**任务签名**（步数档 × 本轮工具集 × 是否"只说不做" × 模型族）
  聚类，真实跑完的轮次才进统计 —— 中位数 / 90 分位 / **偏移系数**（学出"模型一贯偏乐观"）/
  命中率 / 最近样例。下一次提问把这些一起给模型，让它**自我纠偏**。
- **原本没有任何预计时间**：第一次跑时统计是空的，提问里**明说"还没有历史"**（不编数字），
  模型没给 / 给得不合法时退到同类经验推算并**如实标注来源**，绝不冒充模型给的。
- 异常中止 / 出错中止的轮次**不进学习样本**（时长不是"完成时间"，不污染经验）。

### 思考过程不再"回复完成后变少"（真事故）
- **用户看到的**：思考过程本来内容很多，回复一落地，思考块里只剩一点点。
- **根因**：界面流式显示的是**整轮对话所有轮次**的思考（主进程逐增量广播 → 渲染层累加到一个缓冲），
  而工具循环把"**最后一轮**响应"当作最终回复 ⇒ 思考、聊天日志、接口返回值三处都只留最后一轮。
- **修法**：工具循环按轮累积思考再**合并**回最终响应（轮与轮之间空行分隔），
  界面怎么看（流式中 / 落地后）都是同一份完整内容。
- **顺带**：流式增量限频改成「**攒着 + 尾随**」（原实现把密集增量直接丢掉 ⇒ 流式里有洞，看着比真实内容少）；
  工具轮数上限不再被静默砍到 8（设置里填 12/32 就真能跑满）。

### 决策卡仍然没声音（第三次报修，真事故）
- **根因（两个叠加）**：
  1. **`raf` 把同帧的回调静默丢掉**：老实现是"同帧只跑第一个"（`if (__rafThrottle) return`），
     而主刷新循环一个 tick 里连调 8 个 `raf(...)` ⇒ 除第一个全丢。
     `renderAiQuestions`（决策卡的轮询发现）**永远排第二 ⇒ 从来没跑过**：
     主进程没广播的卡片既不显示、也不响铃。
     同类受害者：`refreshCost` / `shuaxinZhixingqiji` / `refreshSessionBoard` / `refreshMembers` /
     `checkLastError` / `renderProjectMemoryPanel` / `refreshJoinBadge`。
  2. **音效逻辑被"没选中会话就 return"短路**：`renderAiQuestions` 开头
     `if (!host || !state.selectedChat) return` 把整段音效逻辑一起挡掉 ——
     冷启动还没选会话时，卡片跳出来一声不响。
- **修法**：`raf` 改成**按帧排队 + 全部执行**（单个回调抛错也不连累别人），并补
  「隐藏窗口 rAF 停发」的兜底定时器；决策卡改**专用心跳**（1.2s，普通定时器，不依赖 rAF）；
  音效与"卡片画不画得出来"**彻底解耦**（没选中会话也照响），广播与轮询**共用一本账**
  （只在**真的播出去**才记账 ⇒ 不会响两遍、也不会漏）。
- **加保险**：显式关掉 Chromium 的用户手势要求（`autoplay-policy` 命令行开关 + 窗口级
  `autoplayPolicy`），启动即预热三种提示音，失败时"手势 + 定时"双通道补播。

## 2026-10-05 v0.2.2（新版本 · 真机验收修复 2）

### 杜绝闪退 / 长回复被截
- **实例进程不再用 electron.exe 当 Node**：以前 `spawn(process.execPath)` 会把每个牛马实例
  以「第二个 Electron 应用」的姿态启动（拉 GPU/网络进程、抢单实例锁、窗口一闪就退）——
  这是真机上的**闪退根因**。现在用捆绑 Node，并强制 `ELECTRON_RUN_AS_NODE=1`。
- **崩坏防护**：渲染/GPU/子进程挂掉时接住并重建窗口，不把一次崩溃变成应用闪退；
