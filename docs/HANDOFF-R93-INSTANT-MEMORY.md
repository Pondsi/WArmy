# 第 93 轮交接 · “记住”与反复踩坑的即时处理

> 用户问：反复踩坑 / 用户明确说“要记住”时，现在是怎么处理的？有即时方案吗？还是只靠事后归档？

## 1. 改之前（如实回答）

- **用户明确说“记住”**：
  - 模型如果主动调用 `knowledge_add`，会立即进知识库；
  - 否则主要靠**事后归档**：`zhengLiYinXiang` 扫描用户原话里的“以后/每次/记住…”写进印象；`guiNaDuanJiYi` 从归档摘要里抽短句进短记忆；
  - **没有宿主的“即时捕捉”**：模型不调工具、又还没归档时，这句话只留在聊天记录里。
- **反复踩坑**：
  - 同一工具同参数重复会被循环守卫拦下，把上次结果原样回给模型（省时间/省 token）；
  - 审计里会记 `chat.tool-repeat-*`，但**没有把踩坑原因沉淀成知识**；
  - 归档时可能从摘要里抽到，但不保证。
- 所以改之前：**“记住”有概率即时（模型主动写），否则靠归档；踩坑基本靠归档或根本不落。**

## 2. 改之后：两条即时链路

### 2.1 用户明确说“记住” ⇒ 当场写知识库

`jiShiJiZhuYongHuHua(sessionId, userText)`：

- 只在**真实用户轮**执行（`!xiaoXi.internal`），续派轮不重复写。
- 按句号/问号/感叹号/换行拆句，取 4–200 字、命中
  `记住|记一下|别忘|以后|今后|每次|永远|一直|不要再|别再|不许再|请务必|约定` 的句子；
- 过滤“你记得吗/还记得吗”这类反问；
- 写入本会话**可写的知识层**：
  - 本机牛马 → 私密层（最严）；
  - 项目 → 内部层；
  - 群聊 → 会话层（只能写会话层）。
- 事件 id 用文本 hash 去重；同一句重复说只更新时间。
- 审计 `memory.instant-remember`。
- 本轮还会在 system 里加一句 `【即时记忆 · 已当场写进本会话知识库】` 并列出句子，告诉模型“已经记下，不要说记不住”。

### 2.2 工具失败/被守卫拦下 ⇒ 当场记“踩坑”

`jiLuGongJu(...)` 失败时调用 `jiShiJiZhuCaiKeng(sessionId, tool, why)`：

- 写入内部层（群聊回落到会话层）；
- 标题 `踩坑·<tool>`，正文为失败原因（截 400 字），来源 `host:pitfall`；
- 文本 hash 去重；
- 过滤常规“权限/授权/拒绝/预算/重复/not-a-file/destination-exists”等，避免把普通拒绝当踩坑；
- 审计 `memory.instant-pitfall`；
- 操作记录（执行过程展开明细）新增「原因」一行，失败原因可见。

## 3. 与归档、短记忆的关系

- 即时写入的是**知识库条目**，不是直接改短记忆；短记忆仍然只由归档按“使用频率”更新。
- 这些条目下一次被 `knowledge_query` 命中后 `useCount` 增加，归档时就能进入短记忆；没被用过就留在知识库里，可 recall。
- 这样不会让“随口一句记住”立刻占满每轮都发的短记忆，也不会丢。

## 4. 验证

`verify-r93-memory-security` 真机部分（`WARMY_TEST_HOOKS=1` 专用接缝）：

- “以后都用中文回答，记住这一点。今天天气不错。” ⇒ 只写第一句，普通闲聊不写。
- `write_file` 的 `ENOENT` ⇒ 写 `踩坑·write_file`。
- `read_file` 的“权限不足，未授权” ⇒ 不写（常规权限拒绝不算踩坑）。

## 5. 最坏情况 / 边界

- 用户说“记住”但句子是反讽/引用别人的话：宿主按字面写入；模型看到的是原话，需要自己判断。没有做语义分类，避免误删。
- 一句话里多个独立要求：目前按句拆，每句最多 5 条；超出的这轮不写，后续归档仍可补。
- 工具失败原因可能包含路径/错误码，写进内部知识库；不会写进会话公开层（群聊只写会话层，项目写内部层）。
- 这些是**即时沉淀**，不是“保证模型永远遵守”；遵守仍靠每轮注入与模型执行。
