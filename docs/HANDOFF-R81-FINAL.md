## 2. 28/29：第四列的“印象 / 项目记忆”是什么

### 28、群聊第四列

- **项目记忆**：这个群/项目共享的事实与约定（目标、术语、当前决定、项目规矩）。创建者维护，成员和牛马可见；数据在 `groups.json` 的 `project.memory`，读取 8000 字、注入 1200 字，超限会明确标截断。
- **印象**：不是“群的印象”，而是**当前会话视角下牛马对你的印象**（你在该群的称呼、分工、偏好）。按会话存副本，避免把 A 群的印象带进 B 群。
- 与「我的」页印象的关系：底层同一套“对你的长期理解”（默认 `yinxiang.md`）；群聊里是按会话的副本，改一处另一处下次渲染同源。
- 注意：**规范卡只在项目会话显示**；群聊/联系人/单聊默认没有规范。若你在群聊看到了规范，是旧布局手动加回的，已在渲染时强制隐藏。

### 29、我的牛马第四列

- **印象**：牛马在后台归档时归纳出的、对**你这个人**的长期理解（喜欢什么、习惯、长期要求、想让它记住的事）。默认所有牛马共用一份；单聊可按会话存副本。
- 与「我的」页印象：**同一份数据的两个入口**；「我的」页是全局主副本，单聊第四列是该会话副本。
- 我的牛马默认没有「规范」卡，也没有「项目记忆」（项目记忆只在真正的项目里出现）。

优先级：硬门禁 > 道 > 术 > 规范 > 教条 > 束缚 > 工具 > 软门禁 > 认知 > 印象。

## 3. 仍需用户协助/决策（逐项：是什么、方案、优缺点、例子、最坏情况）

### A. #106 会话级路由（方案 B）

- **是什么**：发送前按会话选路、失败重试、全部失败时只读并广播“网络不可用”。
- **现状**：没有真实聊天传输；`HuiHuaLuYou`/`touDiDaoSuoYou` 只是纯逻辑。
- **方案**：
  - B1 先接 mesh 聊天通道：改动小、局域网可用；公网仍需中继。
  - B2 先接 FWArmy 中继：公网可用；要写中继客户端、outbox、回执。
- **例子**：A 服务器挂了自动切 B；全挂时消息保持待发、界面显示“未送达”，不写绿勾。
- **最坏**：只做发送不做回执 ⇒ 用户以为发出去了，对端没收到；只做选路不做 outbox ⇒ 重启丢待发。
- **需要你定**：先 B1 还是 B2。

### B. #108 角色矩阵 + 审批 + 会话锚点（方案 B）

- **现状**：`group-store` 只有 role/setAdmin；审批、证书、名片 QR、锚点未接。
- **锚点设计**：不要随机 ID；建议每会话 Ed25519 密钥，公钥指纹做锚点，私钥只在本机安全存储，名片带指纹+一次性 token，换网只换地址。
- **例子**：换 Wi-Fi/换服务器后，对方仍用同一指纹验签，不会认错会话。
- **最坏**：只做随机 ID ⇒ 恶意中继可冒充；锚点私钥不备份 ⇒ 换机后老会话无法继续。
- **需要你定**：是否采用 Ed25519 指纹；联系人是否先做“安全码 + TOFU”。

### C. #103 知识库三层授权（方案 B）

- **现状**：`knowledge-base` 只有 allow 矩阵；第四列三勾选、写权限后端复核、用户切换未接。
- **默认值**：群聊=会话；项目=会话+内部；联系人=会话；我的牛马=三层。
- **建议**：写默认只允许会话层；内部层写仅 creator/admin；私密层写仅本人；共享会话归档默认关。
- **例子**：项目成员能读内部层，但不能写；切换用户只看到对方公开层。
- **最坏**：默认勾错 ⇒ 私密层越权可见；必须后端再校验，不能只信前端。
- **需要你定**：是否接受上述写/归档默认。

### D. #109 模型逐条校对（方案 B）

- **是什么**：导出键值 → 模型只改措辞 → 机器校验键/占位符/结构/专名/长度/承诺强度 → 人工抽检 → diff + 回滚。
- **现状**：只有设计与例子；自动链路未接。
- **例子**：模型把 `{ming}` 改成 `{nom}` ⇒ 整批拒绝；把“不保证送达”改成“保证” ⇒ 拒绝。
- **最坏**：模型改错法律含义；所以必须白名单、校验、抽检、回滚，且不碰 IPC/协议/许可证。
- **需要你定**：是否允许跑一次全量校对（会产生模型费用）。

### E. #112 99 项右键分类（方案 B）

- **现状**：仓库只有 `TASKS-99.md`（99 个开发任务），**没有 99 项右键清单**。

- **最坏**：硬凑 99 项 ⇒ 分类错乱、拖动丢配置、用户找不到功能。

### F. #113/#115 接入向导 + 连通性检测（方案 B）
