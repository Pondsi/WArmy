## 1. 技能/插件目录的加密边界：选 C（拆分）

- **可重新下载的代码走明文**：`userData/skills`、`scan-dirs` 内由外部 Node/Python 解释器直接执行的脚本（例如内置 mcp-bridge 的 `bridge.mjs`）不再逐文件加密，避免外部解释器读到密文。
- **配置仍加密**：技能/插件的配置、凭据、用户数据留在加密边界内。
- **执行时生成最小副本**：需要隔离或改写的执行场景，生成最小临时副本，用完即删；不让外部解释器直接跑加密仓库。
- **状态：已实施**（`verify-r120-plugin-code-plain` 30/30 + `verify-r121-decisions` 44/44 的执行副本部分）：明文目录 ACL、旧密文迁移、审计事件、失败保留原密文、外部解释器可执行 + 配置文件仍密文；执行前复制最小副本（入口+清单+解密配置到 0700 临时目录，用完删除）。详见 [`DECISIONS-R121.md`](./DECISIONS-R121.md) §1。

## 2. run_shell 的命令隔离：选 C（混合）

- **默认限定工作区**：cwd 默认锁在会话工作区；路径越界不静默放行。
- **环境变量白名单**：只传系统/描述性变量，密钥类变量一律不传（与容器执行层同一口径）。
- **进程树清理**：超时/停止时清理整棵进程树，不留孤儿进程（Windows Job Object / POSIX 进程组）。
- **越界操作改一次性「宿主执行」授权**：不再直接硬拒，也不静默降级；用户同意才执行，并记账。
- **授权支持一次性与永久两种**：相同内容（同一规范化命令 + 同一作用域）可永久授权；永久授权必须可见、可撤销、可审计。
- **状态：已实施（永久授权账本见第 121 轮）。** `run_shell` 具备工作区 cwd 解析、越界一次性授权、环境变量白名单、Windows `taskkill /T /F` 与 POSIX 进程组清理、输出上限；第 121 轮新增**永久授权账本**（相同规范化命令+相同目录可永久同意，设置页可见/可撤销，使用/新增/撤销均审计）。**未做**：容器内命令执行。
- **容器/沙箱范围**：只作为「项目」和「牛马」创建时的可选项；联系人、群聊没有也不需要容器或沙箱。
