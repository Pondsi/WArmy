## 0. 项目目标与理念

### 0.1 一句话目标

做一个 **本地优先（local-first）** 的多智能体群聊桌面应用：用户养一队 AI「牛马/社畜」，在群聊里用人机混合协作完成真实工作；跨设备可组网协作；**注入模型的上下文有固定上限，但不丢失任何历史细节**。

### 0.2 产品理念（必须贯穿所有功能）

| # | 理念 | 含义 | 反例（禁止） |
|---|------|------|--------------|
| 1 | **诚实** | 状态、错误、能力边界如实展示；不假装成功 | 容器未就绪却在主机上开发并显示「正常」 |
| 2 | **有界上下文，细节不丢** | 注入模型的是日志的**有界视图**；原文 JSONL 永在，可检索回原文 | 把超长历史原样塞进模型，或静默丢消息 |
| 3 | **本地优先** | 默认不依赖云；数据在本机 userData；审计绝不上传 | 把聊天/密钥上传到第三方 |
| 4 | **用户主权** | 模型、成本、端口、权限由用户决定；系统只给框架与建议 | 静默换端口、静默扣费、静默授权 |
| 5 | **单一事实来源** | JSONL 只追加是唯一事实；SQLite/投影可丢弃重建 | 直接改写历史日志中间内容 |
| 6 | **写入者唯一** | 每类数据只有一个合法写入者 | 多处同时写 board/memory 导致分叉 |
| 7 | **防过度执行** | 门禁/脚本/固件有触发条件与节流，不「每次对话都跑全家桶」 | 每条消息都跑全部 verify |
| 8 | **可交接** | 文档、门禁、命名、IPC 形参可被外人读懂并复现 | 只有作者本机能跑通 |

### 0.3 核心承诺（验收总纲）

1. **发给模型的全部内容都有固定上限**（预算可配，且**预算 = 全部内容**而不是只算历史；下限 = 实测固定开销），
   裁掉的部分变成指针，模型可用 `recall`/`retrieve` 取回；**日志里始终是完整原文**（"有界"发生在投影与视图，不发生在写入）。
2. **UI 聊天区永远显示完整真实记录**（懒加载只是渲染性能手段，不是删数据）。  
3. **端口绑定失败绝不静默换端口**；只展示建议候选，由用户点选。  
4. **容器项目未就绪 = 对成员等同「创建者下线」**，历史仍可读；不新造第三种状态。  
5. **远程 AI 无痕执行**（incognito）：工具路由回创建者设备，远程设备本地零痕迹。  
6. **值班权仅限本机实例**；远程 AI 永不作为值班者。

## 3. 功能需求（可验收）

### 3.1 多实例管理（我的牛马）

- 创建 / 启动 / 停止 / 删除多个 dsh 智能体实例。
- 每实例：独立名称、工作区、插件、会话、人格文件、认知注入（.md）、默认模型、回退链。
- 启动时按本机硬件给出**建议最大实例数**（用户可自行突破或降低）。
- 状态持久化；重启后可恢复。

**验收**：`listInstances`/`spawnInstance`/`stopInstance` IPC；UI「我的牛马」页可增删改。

### 3.2 会话类型

| 类型 | 内部代号 | AI 行为 | 远程 AI | 右栏 |
|------|----------|---------|---------|------|
| 项目（内部群） | `internal` | 值班编排 + 执行者完整工具 | 可加入，权限≈创建者 AI，无痕 | 状态/文件/进度/模型/目录/成员/**知识库+摘要** |
| 外部群 | `external` / `externalGroup` | **仅 @ 响应**，否则静默；仅聊天+看板 | 仅聊天，禁工具/文件/记忆 | 知识库+摘要+成员+模型 |
| 单 AI | `single` | 直接对话，完整能力 | — | 项目状态类面板；成员栏不显示 |
| 联系人 | `externalChat` | 人与人/人与远程 | — | 知识库+摘要；无成员栏 |

### 3.3 群聊与值班编排

- 群创建后按进群顺序编号。
- **值班者只在本机实例中产生**；远程 AI 永不值班。
- 非定向：序号最小的空闲值班者听取并编排；忙则 +1 顺延；可指定固定值班（忙则排队）；可设纯调度值班。
- **值班者自执行**：用户明确要求 / 没有执行者 / 其他执行者全部失败 / 执行者无法完成置信度 >65% 且值班者 <45% 时可自执行；**其他执行者全部失败时不再看置信度，直接兜底**；用户明确禁止值班者自己执行时除外（第 102 轮定稿）。
- 定向模式：用户必须 @ 实例；无值班编排。
- 指令插入三级：默认外循环后（queue）；可手动停止；可内循环插入（UI 警告）。
- 紧急度：P0 停止 / P1 立即插入（手动）/ P2 排队（默认）/ P3 自动兜底。**紧急度归用户**。
- **执行者协议（第 48 轮，ADR000 P5）**：
  - 派给多个执行者的同一任务共用一块**任务黑板**：只追加（改口新写一条并声明替代哪条）、每条带来源（宿主盖章）与记忆库 recordId；
    执行者用 `heiban_read / heiban_write` 读写；进执行者上下文的只有有界摘要 + 取回指针（O(任务规模)）。
  - 执行者交回**结构化蒸馏**（结论有硬上限、事实/决定/未决问题/产物），宿主逐个核实产物是否真的存在，没找到的当场点名；
    结论超长时完整原文存进记忆库、回复里给可执行的 retrieve 指针（存不上就如实说）。
  - 同一主题、不同执行者、说法不同 ⇒ 作为冲突摆在回复里交值班者或用户裁决，系统不替人选。
  - 队列冲刷与主路径走同一套执行者协议；排队的消息必须在本轮结束后真的被处理（不许因为成员还标着忙而一直排着）。

**验收**：Router 队列不丢弃且可持久化（`router-queues.json`）；`verify-router-queue.mjs`；执行者协议 `dev/gates/verify-r48-heiban.mjs`（fast）+ `verify-round20-team.mjs`（真实模型，Ollama 与 MiMo 各一遍）。

### 3.4 看板

- 用户**不能直接改看板**；只能自然语言 → 值班解析 → `board.jsonl`。
- 仅 duty 可写看板。
- 任务树：`新建任务 父任务 / 子任务`；父进度 = 子平均。
- 外部聚合看板只读；会话内嵌看板与聚合共用数据。

### 3.5 项目记忆（project.memory）

| | 项目 MEMORY | memory-os 流水 |
|--|-------------|----------------|
| 角色 | **当前有效**规矩/目标（覆盖式） | 会话/工具历史（JSONL 唯一事实） |
| 落点 | `groups.json` → `project.memory` | `userData/memory/fast-memory.jsonl` |
| 注入 | 值班上下文 `[项目记忆]`，**≤1200 字** | 有界视图 + recall/retrieve |

IPC：`warmy:project-memory-get/set`（set 必须 read-back）。

### 3.6 上下文预算与超限（第 44 轮后半改口径）

- UI 聊天 = 完整真实历史（懒加载窗口，默认约 20–40 条/次，可上滑加载）。
- 模型注入 = `renderBoundedView`：冻结头 + 最近尾部 + 中间指针。
- **预算 = 所有发给模型的内容**（不是"只算历史视图"）：
  `道 + 规矩 + 印象 + 产品门禁 + 身份/身份锚 + 人设 + 能力清单 + 知识库 + 归档摘要 + 最近 5 条 user 原文 + 有界视图 + 续派指令 + 步骤账本 + 子模型结果 + 工具规格 + 本轮输入 + 附件（含图片）`。
  预算设成多少，发出去的全部内容就是这个数（实现：`yuSuan-jiage.ts` 分段计价 + `fenPeiYuSuan` 分配，审计 `chat.budget.allocated` 每轮可查每段多大）。
- **下限 = 实测固定开销**（"不可再小的预算"）：滑杆最小值由上一轮真实量出的固定开销决定，不是写死的 2048。
  **上限可到 100%**（实际执行留 5% 余量防超窗）。窗口真装不下固定开销时**如实说**
  （`ctx.budget.overWindow`：「固定开销 ≈N tokens 已超过该模型窗口」）并走降级到"停止发送"，**不许把滑杆顶死假装能选**。
- **预算不足时的降级顺序**（写在代码里，不许随机挑一段压）：
  ① 「最近 5 条 user 原文」摘要成短摘录 + 可执行指针 → ② 本轮输入自己也超长 ⇒ 本轮原文也摘要（原文仍在日志里，指针告诉模型怎么取回）→
  ③（有图）判能不能分次 → 降分辨率 → 减张数 → ④ 视图收缩 → ④·5 固定开销自己就装不下 ⇒ 先压**允许压的段**
  （能力清单/知识库/人设…，**道/规矩/印象/产品门禁/身份锚 一条都不许动**），还不够就把本轮工具面按 12→6 截尾（并当场告诉模型工具被收窄）→
  ④·6 **让出我们自己留的余量**（2% 安全垫让完、输出预留退到地板 `max(2048, 窗口×4%)`、执行余量 5%→2%）→
  ⑤ 仍不够 ⇒ **停止发送并触发异常系统**（警告音按勾选、显示「继续/重试」、写出"窗口多少 / 各段多大 / 还差多少 / 能怎么办"）。
  ⚠️ 停止必须真的结束这一轮：以前在收缩重试的回调里 `return` 会被壳吞成"该模型上下文太小（已自动收缩重试到最小值仍失败）"，具体原因全丢。
  ⚠️ ④·6 不是"偷偷超发"：让的是**我们加的垫子**（估算用的是分脚本上界，实测真实/上界 ≈0.64–0.89，本来就比 2% 厚），
  让完仍装不下照样停止发送并如实报；每一次让都写审计 `chat.budget.give-back-reserve`（让了多少、留位从多少退到多少、让完还缺不缺）。
  ⚠️ 让了就得**两边一起让**：输入窗口按"只给输出留 2048（或窗口×4%）"放行，发送侧的 `maxTokens` 也必须夹到同一个数
  （审计 `chat.budget.output-cap-lowered`）—— 否则输入 + 输出照样顶穿窗口，供应商 400。
- **单轮用户内容上限 10M 字符**；发送前必须整理到不超预算（原文仍完整进日志，见 §3.7）。
- **溢出保护**：预算的 token 数被"窗口 − 2%（至少 128）"夹住，分配时用的窗口还要再减掉**本轮输出预留**
  （长文/加强回复 12288、其余 4096，用户在额度里设了上限就以上限为准）—— 贴边设预算等于每次都赌误差方向。
- **图片**（第 45 轮实现，门禁 `verify-r44-yuSuan.mjs` ⑧）：
  · **计入预算**：按**真实像素**折视觉 token（不是按文件字节猜），每张带 `宽×高` 与图块同序保存，另乘 1.2 的安全加价；
  · **上限**：单轮 8 张、单张解码前 6MB / 规范化后 8M 字符；超限的**逐张登记**"为什么没喂给模型"，不静默丢；
  · **只发给支持看图的模型**：判据唯一（`moXingKeyiKanTu` = 探测事实 → 官方规格表 → 只按文本），
    在"要不要转交"与"合并图片块之前"各判一次；不支持的模型收到的是文字描述，图片**不占它的预算**；
  · **分次发送**要同时满足两条：单张 + 固定开销放得下、**且本轮没有跨图对比这类不可分割需求**（"对比/哪张/差异/前后/vs…"命中就不分）；
  · **装不下**走上面的阶梯，最后停止并触发异常系统；
  · **校准**：带图的轮不再整轮跳过 —— 从供应商回读里扣掉图片的视觉 token，剩下的才拿去校准文字系数。
- **迟注入层也计入预算且不膨胀**（ADR000「注入量恒定」）：视图渲染之后才拼上去的步骤账本（≤4000 字）、
  子模型结果与分次看图描述（≤6000 字）都**先在预算里留出份额、注入时按同一上限截断**，超出部分如实标注。
- **宿主前置召回**（用户 #8 的另一半）：装配阶段就用本轮内容主动 `recallScoped` 取 ≤3 条历史线索注入，
  份额随本轮预算缩放（6%，夹在 600–2400 字），**在计价之前**入账（所以它挤掉的是视图余额，不是额外加），
  记忆服务未就绪 / 800ms 超时 / 报错一律按"没召回"处理并留痕；`设置.preRecall` 可关。
- **归档摘要不膨胀**（用户 #10）：注入不再是"末 8 条 → 截 3000 字"，而是最近的逐条保留 + 更早的合并去重，
  **注入总量与归档条数无关**，装不下的条数**写在正文里**并给出取回路径，份额随本轮预算缩放（8%，夹在 1200–8000 字）。
- 超限重试：**100% → 60% → 35% → 20%**，最小约 2048 tokens；仍失败则**如实**提示 `chat.contextTooSmall`。
- 群聊：滑块隐藏，后端自动收敛；联系人场景不适用同一套项目预算语义。
- **token 不再靠猜**（第 44 轮后半，用户点名优先）：单一口径 `token-jiliang.ts`（分脚本紧上界）
  + 供应商回读校准，精确到 **`供应商 / 模型 / 密度桶`** 三段（不同供应商或不同模型分词方法可能不同，不许混）；
  没有回读的模型用**该桶平均法**，一次回读都没有时用**先验**（仍比旧的"万能 1.6"准）；
  每次回读都记进观测史，**归档时按全量记录重算**（详见 `docs/MEMORY-SYSTEM.md` §9）。

### 3.6.1 不丢与有界的分工（第 44 轮后半定稿，取代旧的"写入前先折叠"）

- **JSONL 是唯一事实来源 ⇒ 存整条原文**，一个字都不许在写入时丢掉（旧缺陷：`beforeLog` 先折叠，中段永久消失，`retrieve` 拿回半截）。
- **投影（SQLite）只放 16K 索引预览**：够"找到"，不够"复述"；`retrieve` 一律**优先读 JSONL 原文**，
  退回投影时 `via` 如实标成 `sqlite:*-预览`。
- **进程内镜像与视图存预览**，所以"有界"仍然成立且与日志总长解耦；重启恢复**按会话分页**
  （每会话 120 条 / 最近 60 个会话 / 每会话至少保住 2 万字符），不再"一个会话吃满全局 400 条、其它会话重启即失忆"。

### 5.1 三级安全模式

| 维度 | 完全授权 | 常规（默认） | 严格 |
|------|----------|--------------|------|
| 脚本/工具/Skill 调用 | 无需审核 | 首次四选一（全局持久/项目持久/一次/拒绝） | 每次仅「允许一次」 |

| 工作区外写 | 自由（程序安装目录、其他会话工作区/历史除外，需单独授权一次） | 一次/24h/项目区/全局区 | 每次一次 |

- **完全授权的边界（第 102 轮用户定稿）**：完全授权 = 对“我们的程序本身以及相关会话数据”之外的一切开放；程序安装目录、其他会话工作区/历史/账号设置文件**不自动放行**，必须在单独授权卡上明确同意一次；命令/文件/打开/下载/LSP 共用同一禁止区判据。

- 审计：`userData/audit/audit.jsonl`，**绝不上传**，用户可清空。
- 权限过滤**先于**相关性检索。
- 密钥：优先 SafeStorage；`WARMY_ALLOW_PLAINTEXT_KEYS=1` 仅开发，且打 `plain` 标记。

## 永远性要求：启动 / 使用本应用**不启动 WSL**

> 产品主定稿（两次反馈后成为永久要求）："启动这个应用不会启动 wsl"。

**为什么**：`wsl.exe` 的 `--version` / `-l -v` 在 Windows 上会把 WSL 服务拉起来。以前
"打开会话/新窗口 → 查项目状态 → 全量探测运行时"这条例行路径会顺手 spawn `wsl.exe`，
用户看到的现象就是"打开应用/新窗口触发了打开 WSL"。

**规则**：
1. **例行路径一律静默**：项目状态查询等自动探测**不许** spawn `wsl.exe`（`probeWsl` 在非 deep 时
   一个 wsl.exe 都不启动，如实报 `not-probed`，并在界面说明"只有显式点探测才会查"）。
2. **只有用户显式动作才允许查询**：设置 → 功能 → 容器 的「查看本机已有容器」按钮（IPC 传 `deep: true`）。
3. **即便显式查询，也不代为启动发行版**：`wsl -l -v` 里的 Stopped 就报 Stopped，不跑 `wsl -d <发行版> -- true`。
4. **实例列表**：引擎未启动时实例区禁用、不可展开（既有的产品规则）。

**门禁（永久，不许回退）**：`packages/app-shell/scripts/verify-no-wsl-start.mjs`
- 动态：启动应用 → 走真实路径选中会话 → 打开新窗口，断言 `wsl.exe`/`wslhost.exe` 进程数不变、
  各发行版状态不变；本机没有 WSL 时如实跳过动态部分（不假通过）。
- 静态：`probeWsl` 默认静默、项目状态查询不传 deep、只有显式探测才 deep。
- 已加入门禁列表（17 项之外的第 18 项）。
