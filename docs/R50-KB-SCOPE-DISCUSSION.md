# 知识库作用域 · 讨论稿（对齐调研 + 本产品现状）

> 依据：CoALA / LangChain Memory / Claude Projects / OpenAI Memory / Mem0 / Zep / LlamaIndex / MemGPT（来源见文末）。
> 本产品已有：`packages/knowledge-base`、工具 `knowledge_query` / `knowledge_add`、会话级 `sess-*`、项目级 `grp-*`、自动归档、删除 API、与 `recall` 记忆互补。

---

## 一、知识该分哪几类（要不要都进库）

| 类型 | 例子 | 建议 | 理由 |
|---|---|---|---|
| **程序性（怎么做）** | 踩坑、操作步骤、工具用法、检查清单 | **进**（独立 kind=procedure） | 最容易复用；Claude `feedback`/技能层同思路 |
| **语义（是什么）** | 客户是谁、项目目标、术语、人设约束 | **进**（entity） | 现有 entity 模型已覆盖 |
| **情景（发生过什么）** | 「上次甲方否了 A 方案」「曾经部署失败因为 X」 | **进**（event + 时间） | Zep 双时序：要带「何时有效」 |
| **用户持久要求** | 「永远用中文」「不要自动 commit」「先搜索再写代码」 | **进**（preference，高优先级注入） | 类似 custom instructions，应稳定可见 |
| **规则/合规/道** | 不作恶、密钥不进库、审计要求 | **不进可自动写库**；进「规则文件」人写人审 | 防模型改规则（与「道」同级） |
| **密钥/PII/隐私** | token、身份证、未脱敏合同 | **禁止入库** | 业界硬底线 |
| **会话中间态** | 「正在改这个文件的假设」 | **会话层**，结束降权或晋升，不进长期库 | 避免噪声 |

**推荐**：知识库 = 程序性 + 语义 + 情景 + 偏好；规则走规则文件；密钥/PII 硬拦。

## 二、作用域怎么切（你现在最该定的）

```
全局（道/安全/合规）          ← 人写人审，agent 只读
    ↓ 覆盖/细化
用户偏好（称呼、习惯、禁忌）   ← agent 可低危自动写；高危要确认
    ↓
项目/群（客户、架构、项目史）  ← 成员可读；写要确认或可回滚
    ↓
会话（本轮假设、中间产物）     ← 默认本会话；结束可晋升到项目
    ↓
实例私有（路径、sandbox）     ← 不共享、不进 git
```

### 与本产品对齐的建议

| 现状 | 建议调整 |
|---|---|
| 社交/外部消息进**你的主会话** → 全局 recall 可被套话 | 外部群/人**独立会话 + 独立知识作用域**，禁止读全局 |
| 会话知识 `sess-*`、项目 `grp-*` 已有 | 明确：**项目知识可跨会话读，会话知识默认不跨项目** |
| 自动归档进知识库 | 归档条目标 `source=archive`、置信度中等，可一键回滚 |
| `knowledge_add` 模型可写 | 分两档：**自动**（偏好/踩坑）vs **待确认**（客户结论、共享规则） |

### 全项目是否全部使用？

**不要全部无条件使用。** 建议矩阵：

| 知识 | 全局 | 项目 | 会话 | 实例 |
|---|---|---|---|---|
| 道/安全/合规 | 读 | 读 | 读 | 读 |
| 用户偏好 | **读写** | 读 | 读 | 读 |
| 操作踩坑/工具规则 | 可选全局 | **读写** | 读 | — |
| 客户/项目历史 | — | **读写（宜确认）** | 读 | — |
| 本次任务中间态 | — | 可晋升 | **读写** | — |
| 本地路径/密钥 | — | — | — | **仅本机** |

**冲突消解**：项目 > 用户偏好 > 全局；冲突必须出「裁决卡」而不是模型随便挑（Claude 文档也承认模型会挑）。

## 三、什么时候读、什么时候写

**读（注入/检索）**
1. 固定注入：道 + 用户偏好 + 本项目规则（有界摘要）  
2. 按需：`knowledge_query`（已有）；Self-RAG 式「先判断要不要查」  
3. 优先级：项目指令 > 偏好 > 历史情景；带来源与时间  

**写**
| 场景 | 门槛 |
|---|---|
| 用户明说「记住…」 | 立即写入偏好/知识 |
| 重复踩坑、纠错 | 自动写 `procedure`（可删） |
| 客户结论、合同要点、共享规范 | **人工确认**后写 |
| 模型幻觉/无来源 | **不写**；无出处不进库 |
| 用户否认某条 | **tombstone**（否认记录），检索降权/屏蔽，可追溯 |

**过期**：事件带时间；结项项目归档只读；偏好长期；踩坑可标 `replacedBy`。

## 四、使用方式（对用户/对模型）

**对你**  
- 设置里分页：偏好 / 项目知识 / 踩坑 / 归档  
- 每条可见：内容、来源（谁写的/哪次会话）、置信度、时间、删除/改为「不要再提」  
- 「导入/导出」项目知识，便于换机与审计  

**对模型**  
- 系统提示只给：条数、类型、用法、**查不到不许编**（已有触发器，保留）  
- 工具：`knowledge_query` / `knowledge_add`（已有）+ 建议 `knowledge_forget` / `knowledge_correct`  
- 引用：回答里写「来自知识库：xxx」

## 五、最坏情况与护栏

| 风险 | 最坏 | 护栏 |
|---|---|---|
| 作用域泄漏 | 外部人套出全局隐私 | 外部会话默认隔离；全局 recall 不跨 |
| 幻觉写库 | 错误事实长期污染 | 无来源不写；确认门槛；一键删 |
| 规则被改写 | 安全策略失效 | 规则文件人审，agent 只读 |
| 库无限膨胀 | 检索变差、注入超窗 | 有界摘要 + 时间衰减 + 归档 |
| 用户无法更正 | 不信任 | 删除 + 「不要再提」+ 冲突裁决卡 |

## 六、请你拍板的问题（可直接回编号+选项）

1. **外部社交是否强制独立会话+独立知识？**（推荐：是）  
2. **哪些写入必须你确认？**（推荐：客户结论/共享规则/合规；偏好与踩坑可自动）  
3. **项目知识是否允许跨项目引用？**（推荐：默认否，可对「关联项目」开）  
4. **自动归档进库的条目要不要等价「草稿」待审？**（推荐：先自动+可回滚，稳定后再升正式）  
5. **召回引用粒度**：只给条目名 vs 附原文摘要？（推荐：摘要 ≤300 字 + 来源锚点）  
6. **与 `recall` 记忆库分工**：知识库=结构化事实，recall=对话流水与摘要——是否维持？（推荐：维持，检索结果可互相跳转）
