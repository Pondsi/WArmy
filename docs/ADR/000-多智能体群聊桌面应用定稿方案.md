# 多智能体群聊桌面应用：最终定稿方案（ADR 000）


## 一、对其他AI纠错的裁决

### ✅ 采纳的纠正

**1. V4 Pro 并未下线，官方已撤回决定**

前序AI指出“V4 Pro已于9月14日下线”是错误的。联网核查确认：DeepSeek在9月11日紧急撤回了下线决定，宣布“决定在2026年9月14日之后继续提供DeepSeek V4 Pro的API调用服务，计费方式保持不变”。虽然V4.1 Flash在性能、费用、速度上已全面超越V4 Pro，但不应在代码层面硬编码封杀V4 Pro，应保留用户自由选择模型的权利。

**2. “零原生模块”与better-sqlite3的进程边界必须明确**

另一份AI指出方案存在矛盾：不变量第4条禁止主/渲染进程加载`.node`，但L2记忆层计划使用better-sqlite3。**验证结果**：社区已有成熟实现，Signal Desktop等大型Electron应用将better-sqlite3隔离在Worker中，通过IPC与主进程通信。方案中“bundled Node + child_process.spawn”策略已正确隔离原生模块，需在架构图中明确画出L2记忆子进程的边界。

**3. Windows提权放弃独立C++ Helper，改用gsudo**

**验证结果**：gsudo支持凭据缓存（Elevate many times with only one UAC popup），在Electron中可用。开发与维护成本远低于维护独立C++ Helper。

**4. Session V3迁移必须强制备份**

**验证结果**：官方Release Note明确要求“先备份`%USERPROFILE%\.dsh\sessions`文件夹，再升级”。迁移前强制备份，保留原文件，Release Note明确告知用户“升级后无法回退到旧版本而不丢失数据”。

**5. WASM SIMD兼容性兜底**

**验证结果**：ONNX Runtime Web在部分用户中遇到SIMD检测失败问题。解决方案：运行时检测SIMD支持，准备非SIMD版本的ONNX模型文件作为回退。

### ⚠️ 部分采纳的纠正

**6. 审计日志隐私边界**

采纳建议，明确`audit.jsonl`绝不上传，仅存储在本地，用户可随时清除。

**7. 增加本地回环测试**

采纳建议，在P0 Spike阶段增加“本地回环测试”。

### ❌ 驳回的纠正

**8. “放弃WASM，改用原生Node插件”**

驳回。Electron对WASM SIMD/WebGPU支持已成熟，bge-small在WASM SIMD下推理耗时约15-30ms，满足<50ms目标。引入`.node`将破坏“零原生模块”带来的CI优势，为5-6个平台维护编译环境得不偿失。**坚持WASM路线，启用SIMD + WebGPU后端**。

**9. “better-sqlite3必须放弃，改用sql.js”**

驳回。sql.js基于WASM，性能远低于better-sqlite3，且在大量向量检索场景下会显著下降。Signal Desktop等大型Electron应用已验证better-sqlite3 + Worker线程池方案的可行性。


## 二、需求文档

### 2.1 产品定位

一个基于Electron + dsh的多智能体群聊桌面应用。用户可创建多个独立的dsh智能体实例，将它们拉入群聊，由一个值班者实例统一编排任务。支持跨设备多节点协作，人机混合参与。核心承诺：**注入上下文有固定上限，但不丢失任何历史细节。**

### 2.2 功能需求

**多实例管理**
- 用户可创建、启动、停止、删除多个dsh智能体实例
- 每个实例有独立名称、工作区、插件、会话记录、人格文件
- 应用启动时根据硬件给出建议最大实例数，用户自行决定
- 实例可随时关闭和开启，状态持久化

**群聊系统**
- 用户可将任意实例拉入群聊，群聊创建后按进群顺序排列序号
- **值班者只在本机实例中产生**，远程设备上的AI永远不作为值班者
- 非定向模式下，用户发言由序号最小的值班者听取并编排
- 值班者忙时由+1序号实例接手；可指定固定值班者（忙则排队）；可设“永不参与回复”的纯调度值班者
- 定向模式下，用户必须@实例才回答，无值班者
- 支持多个群聊，每个群聊有独立配置
- 用户可直接在群聊中聊天

**群类型**

| 群类型 | AI响应模式 | AI能力 | 远程AI权限 |
| :--- | :--- | :--- | :--- |
| **内部群** | 值班者编排，执行者干活 | 完整工具/文件/记忆 | 与创建者AI一致，完全接管，无痕执行 |
| **外部群** | **仅@才响应，否则静默** | 仅聊天 + 看板总结 | 仅聊天，禁用工具/文件/记忆 |
| **单AI会话** | 直接对话 | 完整能力 | — |

**跨设备协作**
- 每个安装本产品的设备为独立节点
- 节点上的AI和用户都可以被邀请加入会话（内部群/外部群均可）
- 所有参与者必须是本产品用户（设备已注册）
- 创建者或管理员审批后才能加入
- 邀请令牌一次性、有时效，可随时撤销已配对设备的访问权限
- **远程AI加入内部群后完全被创建者接管**：使用创建者设备上的资源，权限与创建者AI一致，不注入该AI实体设备上的任何记忆/上下文，不在该AI实体设备上留下痕迹
- 远程AI以incognito模式运行，工具调用路由回创建者设备，执行完成后本地零痕迹
- 远程设备只能看到群聊的完整上下文，不能看到调用AI时注入的信息

**角色权限体系**

| 权限项 | 创建者 | 管理员 | 成员 | 外部群成员 |
| :--- | :--- | :--- | :--- | :--- |
| 解散群组 | ✅ | ❌ | ❌ | ❌ |
| 修改群设置 | ✅ | ✅ | ❌ | ❌ |
| 任命/撤销管理员 | ✅ | ❌ | ❌ | ❌ |
| 邀请成员（人/AI） | ✅ | ✅ | ❌ | ❌ |
| 审批入群申请 | ✅ | ✅ | ❌ | ❌ |
| 审批工具/脚本调用 | ✅ | ✅ | ❌ | ❌ |
| 管理持久允许库 | ✅ | ✅ | ❌ | ❌ |
| 查看知识库 | ✅ | ✅ | ✅ | ❌ |
| 与值班者对话 | ✅ | ✅ | ✅ | ✅ |
| 查看看板 | ✅ | ✅ | ✅ | 只读 |

**指令插入**
- 默认：外循环后插入（消息进入`queue.jsonl`，等当前任务完成后执行）
- 用户可手动“停止任务”（返回已完成部分总结，之后手动重新发布对话）
- 用户可手动“内循环后插入”（在下一个工具批次边界注入，UI警告）
- 排队消息可编辑、删除、排序

**状态回溯与回退**
- 每轮对话自动创建检查点（轮起 + 轮末）
- 回退同时回滚对话状态和文件状态
- 检查点数量上限可配置（默认50个）
- CoW优先，shadow-git回退

**看板系统**
- 外部聚合看板：只读，展示所有会话进展，点击跳转
- 会话内嵌看板：**全局只有值班者可修改**
- **用户不能直接在看板中输入任何内容**，只能通过自然语言与值班者对话，由值班者解析为结构化事件后写入`board.jsonl`
- 进度总结报告由值班者定期生成（使用经济型模型，异步后台生成）

**知识库系统**
- 名称驱动知识库：实体（人/组织/材料/地点/概念/工具/项目）+ 属性 + 关联事件 + 证据锚点
- 事件驱动知识库：行为事件 + 工具/方法/结果/预期 + 因果链 + 证据锚点
- 双向索引互查：实体→事件、事件→实体
- 统一检索入口：`knowledge_query`
- 所有会话的原始聊天记录永久保留，知识库归档后证据锚点指向原文

**模型配置**
- 模型不固定，成本不固定，由用户决定
- 系统只提供按角色分配模型的框架：值班者、执行者、摘要/兜底、嵌入模型
- 任务分级调度：P0任务走云端最强模型；P3任务走本地ONNX模型或最便宜API

### 2.3 安全机制需求

**三级安全模式**

| 维度 | 完全授权（危险） | 常规模式（默认） | 严格模式 |
| :--- | :--- | :--- | :--- |
| **脚本/工具/Skill调用** | 无需审核 | 首次审核：全局持久允许 / 当前项目持久允许 / 允许一次 / 拒绝 | 每次授权：仅“允许一次” |
| **脚本/工具/Skill安装** | 无需审核 | 首次审核：同上四选项 | 每次授权：仅“允许一次” |
| **工作区文件读写** | 自由读写 | 自由读写 | 自由读写 |
| **工作区外文件读取** | 自由读取 | 自由读取 | 每次授权：仅“允许一次” |
| **工作区外文件写入** | 自由写入 | 授权：一次 / 24小时 / 放入当前项目工作区 / 放入全局工作区 | 授权：仅“允许一次” |

**持久允许库**：`userData/permissions/allowlist.json`，管理界面支持查看、撤销、修改范围、导出

**审计日志**：`userData/audit/audit.jsonl`，记录所有操作，绝不上传

**系统级Helper Tool**
- macOS：SMAppService，Helper保留在app bundle内
- Windows：gsudo，支持凭据缓存（多次提升只弹一次UAC）


## 三、技术路线

### 3.1 十一条不变量

1. **日志只追加**：JSONL永不重排/重写/插入中间。系统提示词更新走`in-history`机制。
2. **视图有界**：注入给模型的上下文是日志的渲染视图，大小由压缩策略参数控制，与日志总长度解耦。
3. **写入侧压缩**：CCR压缩在内容进入日志之前发生，使日志本身是压缩态。
4. **零原生模块**：Electron主/渲染进程不加载任何`.node`。dsh实例、记忆服务一律`child_process.spawn(捆绑独立Node)`。
5. **JSONL是唯一事实来源**：SQLite是可丢弃、可全量重建的投影。
6. **写入者唯一**：`fast-memory.jsonl`仅值班者、`queue.jsonl`仅Router、SQLite仅记忆服务。
7. **短命执行者**：执行者上下文 = O(任务规模)，任务完成即销毁，只回传蒸馏结论。
8. **紧急度归用户**：P0停止 / P1立即插入为手动按钮；P2排队默认；P3自动兜底。
9. **权限过滤先于相关性检索**。
10. **远程AI无痕执行**：远程AI以incognito模式运行，任务完成后本地不留下任何会话日志、记忆或上下文。注入的信息由创建者组装，远程设备无法拦截。
11. **值班权仅限本机**：值班者只在本机实例中产生，远程设备上的AI永远不作为值班者。

## 四、实施计划

### P0：契约冻结与十项Spike（2-3周）

**Spike 1：5平台bundled Node拉起dsh**
- 下载5平台独立Node.js二进制（Node 22 LTS）
- 在5平台上分别拉起dsh 0.1.5-rc.1
- 验证node-pty / koffi prebuild可得性
- **已知问题**：node-pty在arm64 Electron打包为x64目标时崩溃，上游已修复
- **回退方案**：CI交叉编译产物走extraResources

**Spike 2：better-sqlite3子进程IPC延迟**
- v13.0.3在Node 22（ABI 127）下的prebuild可用性
- 1000次hash点查P50 / P95
- FTS5全文检索（10万条记录）延迟
- **DoD**：hash点查P95 < 5ms；FTS5检索P95 < 20ms

**Spike 3：in-history实测 + 会话恢复缓存Bug**
- 50轮消息，记录每轮命中率
- 第25轮触发`in-history`，验证cacheRead是否保持
- 关闭重启，恢复会话，测量恢复后命中率
- **回退方案**：若失效，改为“系统提示词冻结，任务状态追加消息承载”

**Spike 4：FTS5单字索引 + 短语查询**
- CJK字符间插空格，查询时使用FTS5短语语法
- 验证1字词、2字词、3字词、英文标识符
- **DoD**：2字词命中率100%

**Spike 5：dsh-agent-teams + dsh-memory-plus共存**
- 安装`@nanmicoder/dsh-agent-teams@0.1.17` + DSH 0.1.5-rc.1
- 从GitHub克隆dsh-memory-plus（**尚未发布到npm**，需`git clone`安装）
- **已知风险**：两者都改上下文组装，冲突概率高
- **回退方案**：按序patch或二选一（优先保留memory-plus）

**Spike 6：V4 Pro可用性验证**
- 调用DeepSeek API，确认`deepseek-pro`仍可访问
- **DoD**：V4 Pro API返回正常响应

**Spike 7：onnxruntime-web WASM SIMD/WebGPU嵌入延迟**
- 加载bge-small-zh-v1.5 ONNX int8
- 测试WebGPU → WASM SIMD → 单线程WASM三条路径
- 边界输入测试 + 非SIMD回退
- **DoD**：WebGPU或WASM SIMD P95 < 50ms

**Spike 8：系统级Helper Tool**
- macOS：SMAppService，注意macOS 26存在`fullPath is nil` XPC连接问题
- Windows：gsudo凭据缓存
- **DoD**：修改hosts文件成功

**Spike 9：本地回环测试**
- 无网络环境下验证Electron主进程 → 记忆子进程 → dsh实例通信
- **DoD**：完整生命周期无死锁；停止后进程树归零

**Spike 10：跨设备同步协议验证**
- 验证dsh-agent-cluster文件总线在两节点间的消息互通
- 验证远程AI以incognito模式执行任务后本地零痕迹
- **DoD**：两节点间消息互通；远程AI执行后本地无会话日志
- ⚠️ **本 Spike 已被大幅超过并落地**：去中心化组网 / 身份认证 / 仓库协作的全部需求、评审、
  实现与验证见 **ADR 003**（含 Ed25519 指纹身份、HS1–HS4 双向认证握手 + AES-GCM 会话、

> ⚠️ **P4.5 的交付清单必须补上「成员证书 + 吊销列表」**（见 ADR 003 §附八.8）。
> 原因：本清单只写了 `SyncProtocol`，而 §2.3 第 6 条定的"项目主签发成员证书 + 吊销列表"
> 没有落到任何一个阶段里 —— 这是**遗漏**，不是有意推迟。缺了它就**没有"群内身份恢复"路径**：
> 成员一旦换证，群主无法把"新公钥"认定成"原来那个人"（ADR 003 §附五.1 的第四层兜底依赖它）。
>
> 同理，跨设备/组网部分的**唯一权威描述是 ADR 003**（本表的 `SyncProtocol` 一项以它为准）：
> 其中还包含 IPv6 作为连接阶梯第一档（决策 D2 未落地）、双 CGNAT 的中继兜底、
> DHT 记录默认伪名签名、重放计数必须跨进程重启持久化等已实测结论。
