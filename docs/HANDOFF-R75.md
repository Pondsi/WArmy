## 1. 界面

打开 `http://127.0.0.1:8787/`（或你启动时指定的端口）→ 点顶部「扩网」。

### 1.1 扩网（我连接别人）

- 表单：**名称**（可选，便于区分）+ **地址（IP 或域名）** + **凭据**。
- 地址规则：
  - 只写 `1.2.3.4` 或 `relay.example.com` → 端口默认 **59599**；
  - 写 `1.2.3.4:60000` / `relay.example.com:60000` → 走指定端口；
  - IPv6 写 `[::1]:59599`；
  - 误贴 `https://host:port/path` 会自动剥掉协议和路径。
  - 表单下方有明确提示：**不填端口就是默认 59599**。
- 添加后每行可：**测试**（调用对方 `/api/expand/ping`，回显版本/端口）、**停用/启用**、**移除**。
- 统计：请求、字节、转发、送达、拒绝、离线，以及按每个上游分别统计（`perOutbound`）。

### 1.2 被扩网（别人连接我）

- **一键生成凭据**：生成 `fwnexp_…`，明文**只显示这一次**（带复制按钮）；再次生成会让旧凭据立即失效。
- 生成后显示：凭据前缀、生成时间、最近一次被调用时间与结果。
- 统计：和总览同款卡片 + 明细表，并**按来源分列**（`perSource`），能看到是哪个上游 FWArmy 转来的、成功/离线/队列满各多少。
- 给对方的连接方式：**你的域名或公网 IP:端口**（本机实际监听端口；不写端口对方会按默认 59599 连接，所以监听不是 59599 时必须明确带端口）+ 这个凭据。

## 2. 行为（关键契约）

1. 本机 `/api/relay` 先走本地投递；**只有本地送不到**（收件人离线 / 队列满）才按添加顺序转发给已启用的扩网地址。
2. 转发的是**同一个不透明信封**，不解析内容；`source` 带本机 `instanceId`，`route` 带跳转路径。
3. **只做一跳**：被扩网的一方收到后只尝试本地投递，**不会**再转给它自己的扩网地址；`route` 里出现本机 `instanceId` 直接 409 `loop`。这样避免 A→B→A 的环路。
4. **无论成功失败都如实返回**：成功 `{ok:true,queued:true,instanceId}`；失败 `{ok:false,error:'offline'|'queue-full',...}`，绝不假成功。
5. 所有上游都失败时，原发送方拿到的是失败明细（每个上游的 http 状态/网络错误/耗时），不是笼统的“失败”。
6. 队列仍在内存、TTL 30 秒；**消息信封不落盘**。

## 3. 接口

管理面（仅本机回环 + 同源/无 Origin + JSON）：
- `GET /api/admin/expand` — 完整视图（instanceId、inbound 配置/统计、outbound 列表/统计、perOutbound、perSource）
- `POST /api/admin/expand-inbound` — 生成被扩网凭据（返回一次明文）
- `POST /api/admin/expand-outbound` — 添加上游 `{name,address,credential}`
- `POST /api/admin/expand-update` — 启停/改名
- `POST /api/admin/expand-remove` — 移除上游（保留历史统计）
- `POST /api/admin/expand-test` — 测试上游可达性

业务面（给其他 FWArmy 调用）：
- `POST /api/expand/relay` — `Authorization: Bearer fwnexp_…`，body `{to,envelope,source,route}`
- `GET /api/expand/ping` — 同样鉴权，返回 `{ok,instanceId,product,version,port}`

## 4. 安全与存储

- 被扩网凭据只存 **sha256**，明文不落盘；日志不写凭据明文。
- 扩网凭据需要主动调用对方，因此保存在本机 `data/expand.json`（请只在本机使用，不要外传）。
- 管理面仍然只允许本机回环地址访问。
- `expand.json` 原子写入；损坏时改名保留并按空表启动。
- 顺手修了一个旧缺陷：总览渲染里有一行对已不存在的 `#overviewCreds` 赋值，导致每次刷新都弹「连不上服务器：Cannot set properties of null」。已删除；现在总览/扩网切换不再误报。

## 6. 怎么看到它

1. 若你的 FWArmy 旧实例还开着，**先退出再启动**最新 `fwarmy/dist/FWArmy.exe`（旧进程不会热更新管理页）。
2. 默认地址 `http://127.0.0.1:8787/`，点顶部「扩网」。
3. 被扩网给别人用时：对方要能访问到你的 **公网 IP/域名 + 端口**；本机默认监听回环还是所有网卡，取决于启动参数（见 `fwarmy/README.md` §6）。

## 7. 未完成 / 需要你决定

1. **传输仍是 http**：凭据走 `Authorization: Bearer`，如果跨公网明文传输会被嗅探。要不要上 TLS（自签 / 反向代理 / 内置证书）需要你拍板；在此之前建议只在局域网或 VPN 里互联。
2. **只做一跳**：A→B 送不到时不会继续 B→C。这样做是为了防环路；如果你需要多跳，得加 TTL + 去重表，属于下一步。
3. **转发没有持久重试**：上游 8 秒超时即记失败；没有落盘重试队列。消息本身仍是 30 秒内存队列的实时语义。
4. **每实例只有一个被扩网凭据**：重新生成即旧凭据失效；如果要多凭据/分权限，需要再设计。
5. **公网可达性**：需要端口映射/公网 IP；FWArmy 侧没有做打洞或中继发现。
6. **管理页仍是中文**：扩网页文案未进多语言（FWArmy 管理页目前整体中文）。
7. 第 74 轮遗留仍在：`verify-round34-live` 的 MiMo 双稿红未修；首启十幕待你选型接入。见 `docs/HANDOFF-R74.md` §4。
