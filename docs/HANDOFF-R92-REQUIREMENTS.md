# 第 92 轮交接 · 会话「要求」

> 用户口径：第四列新增提示词卡片「要求」；对话时注入；优先级与短记忆同级但**高于短记忆**、低于术，
> 可被压缩；每会话一份、互相隔离；**完全由用户填写，模型不可更改**（软门禁/产品门禁）；默认空。

## 1. 数据与 UI

- **路径**：`userData/yaoqiu/<sessionId>.md`（每会话一份；文件名净化，防路径穿越）。
- **默认**：文件不存在 = 空；textarea 为空。
- **上限**：2000 字符（`TI_SHI_SHANG_XIAN['要求']`）；输入框 `maxlength` + input 截断 + 主进程 `chaoShangXianRi('要求')` 双重校验；超限保存返回“现在多少字/上限多少字”。
- **卡片**：`#mianBanYaoQiuKuai`，第四列默认卡片（single/internal 都默认有），可拖拽/折叠/从添加卡片下拉加入；带「注入」徽标；默认折叠。
- **IPC**：`warmy:yaoQiuDu` / `warmy:yaoQiuShe`；preload 同名桥。
- **重绘**：进会话、切会话、显隐变化、保存后都会 `renderPanelYaoQiu()`；旧规范卡当年漏了这条入口，本轮一并补上。
- **迁移**：旧 `panCards` 含规范卡时换成要求卡；用户手动删掉要求卡后不会被强行加回。

## 2. 注入

- 位置：`术` 之后、`短记忆` 之前。
- 段标题：`【要求 · 只作用于本会话（用户亲写，仅次于「术」）】`
- 明确写：
  - 高于短记忆/教条/束缚/认知/印象，低于硬门禁、道、术；
  - 只在本会话生效，不许外推到其它会话/牛马/全局；
  - **模型只能读取，不得改写、删除、伪造或“顺手整理”**；
  - 与短记忆冲突以要求为准；与硬门禁/道/术冲突按它们执行并说出冲突。
- 审计：`chat.yaoqiu-injected`。

## 3. 模型不可改（多层防线）

1. **产品硬门禁 E**（`builtin-rules.ts`）：明确“要求只能由用户写，模型不可修改”。
2. **没有写入口**：模型工具清单里没有写 `yaoqiu/` 的工具；文件在 userData，工作区沙箱默认够不到。
3. **文件工具拦截**（`work-tools.ts`）：`write_file` / `edit_file` / `copy_file` / `move_file` 命中 `yaoqiu/…` 直接返回 `yaoqiu-readonly`。
4. **shell 拦截**（`electron-main.ts` run_shell）：命令里出现 `userData/yaoqiu` 或 `%APPDATA%…yaoqiu` 形状直接拒绝。
5. **归档提示**：把要求标为“只读；不得改写/删除”，并要求不要输出对要求的修改建议。

残余风险：完全授权下用混淆命令仍可能绕过 shell 路径匹配；宿主无法在 OS 层禁止任意命令。但明显路径、文件工具、模型工具三条都已堵住。

## 4. 压缩

- 第 3 层：`['短记忆', '要求', '术']`（层内先压短记忆，再要求，最后术）。
- 半极限留 72%、真极限留 45%，段内至少 600 字；道与产品门禁永不动。
