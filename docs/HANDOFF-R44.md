### 项 2：1048.576k 的真根因是**三条独立的洞**，不是一处显示错

用户看到的 `1048.576k` 字面上"没错"（1048.576 × 1000 = 1,048,576），但它暴露了三件事：

1. **显示换算把残渣甩给用户**：旧 `zhanShiDanWei` 只认"整除 1,000,000 才用 m"，于是二进制窗口 1,048,576 落到 `k` 分支并保留三位小数。
   ⇒ 新算法（`packages/app-shell/src/mo-xing-gui-ge.ts`）**先试十进制整除、再试二进制整除**（384000→`384k`，131072→`128k`，1048576→`1m`），都不整除才留 2 位小数，**并且永远把精确 token 数一起带出去**（界面在旁边写 `= 1,048,576 token`）。
2. **事实被显示值污染的风险**：显示成 `1m` 后如果按 `1 × 1,000,000` 存回去，就把 1,048,576 悄悄改成了 1,000,000（预算变小是真事故）。
   ⇒ 存储新增 **`ctxTokens/outTokens`（精确 token 数）**，预算按这一份算；界面带 `yiGai`（这一栏有没有被改过），**没改过就原样写回精确值**。门禁断言"打开后直接点保存 ⇒ 仍是 1,048,576"。
3. **数据本身是错的，还不肯被刷新**（更严重）：
   · 云端端点**问不到长度** —— 第 44 轮实测 MiMo `token-plan-cn/v1/models` 只回 `id/object/owned_by`；旧代码于是落到"默认 128K + 窗口×2 推 tpm ÷4000 推 rpm"，而官方页写的是 **1M / 输出 128K / RPM 100 / TPM 10M** ⇒ 窗口小了 16 倍、rpm 高了 5 倍、tpm 小了 5 倍，三个方向都错。
   · 本地 Ollama **其实问得到**（`num_ctx`/`context_length`），但 `settings.modelCaps` 里存的是**上一版探测失败留下的 0** ⇒ 每个本地模型都被按 128K 走（实测真实值是 131072 / 16384）。
   · 而"拉取模型时已有记录就不覆盖"把**自动快照当成用户输入** ⇒ 这些错值永远刷不掉。
   ⇒ 三处一起改：① 新增**官方规格表** `MODEL_GUIGE`（每条带 `laiYuan` + `heShiRi`，本轮核对的写 2026-10-19，历史遗留的写 `null` ⇒ 界面标"未核对"，不许把没根据的数装成核实过的）；
   ② 额度来源分层**分开显示**（`你的设置` / `拉取信息` / `官方规格表：<出处>（核对于 <日期>）` / `默认 128K（没拉到窗口）`）；
   ③ 快照带 **`ziDong`** 标记 ⇒ **自动快照下次拉取会被重算覆盖**，只有用户亲手点过确定的（`ziDong:false`）才不动；能力缓存 `modelCapsVersion` 3 → **4**（旧缓存不再被采信）。

   另外模态也补了同一条腿：能力探测真判过（`true/false`）才信它，`unknown` 时用官方表声明的 `inTypes/outTypes`（MiMo 官方收文本/图/视频/音频，旧逻辑会登记成"只读文本"）。

**核对过的官方数字**（不是估的）：
- MiMo 四款（`mimo-v2.5` / `-pro` / `v2.6-flash` / `v2.6-pro`）：上下文 **1M**、最大输出 **128K**、**RPM 100**、**TPM 10M**；除 v2.5-pro 外输入含图/视频/音频，输出文本，支持工具调用 —— [MiMo 官网模型页](https://mimo.mi.com/models/zh-CN/mimo-v2.6-flash)、[模型发布](https://mimo.mi.com/docs/zh-CN/updates/model)

### 项 5：T15 微信 iLink / ClawBot —— "未动"的真正原因是**接口路径是猜的**

第 41/42 轮都记"未动"，第 37 轮其实写过一版适配器，但那版**一次都不可能连上**，所以体感与"没做"一致。本轮直连真服务器取证：

| 取证 | 结果 | 结论 |
|---|---|---|
| `POST /cgi-bin/mmwebwx-bin/getupdates`（旧代码写的路径） | **HTTP 404** | 那是老网页微信的接口，iLink 根本没这个路径 ⇒ 旧适配器永远收不到消息 |

### 8.5 留一个**设计权衡**给用户定夺（我没有擅自改阈值）

停滞判据是 `连续 3 次段增量 < max(80, 2%·目标)`（6000 字 ⇒ 120 字）。四次真机样本摊开看：

| 样本 | 段增量序列（宿主报的净字数） | 停在 | 占目标 |
|---|---|---|---|
| 第 39 轮那批老红 | 335 → 279 → 197 → …（**每段都只有 100 上下**） | **436 字** | 7 % |
| `r34-ollama-4` | 590 → 901 → 1340 → 1877 → **106 → 106 → 106** | 2195（续派后 3282） | 37 %→55 % |
| `r34-ollama-1` | … → 4408 → 4839 → 5177 → **104 → 104 → 104** | 5489 | 91 % |
| `r34-ollama-1`（修 `{k}` 后那次） | 1375 → 2129 → 2760 → **105 → 104 → 104** | 3073（最终文件 5852） | 51 %→98 % |

· 后三条是**同一签名**（增量掉成恒定值 ⇒ 反复贴同一段尾巴），叫停叫得对；
· **第一条是边界**：模型全程每段只写 100 字上下、**没有大段过**，于是从冷启动数到第三次就满了 3 次 ⇒ 436 字就叫停。这种"慢而稳定"的写法被当成"写不动"，**判据与它自己的文案（"这段已经写不动了"）不完全一致**。
· 要不要放宽（比如"曾经连续写出过 400+ 字的大段 ⇒ 阈值减半"，或改成"增量近 0 才算停滞 + 内容重复才算停滞"）是**产品取向**决定：
  放宽 ⇒ 更不容易误伤慢写的模型，但反复贴尾巴的模型会多写几段垃圾、也更久才收场。
  本轮**没动阈值**：验收中途改一个调过的启发式，会把"这轮到底改坏了什么"搅浑，而且现有兜底（决策卡 + 「继续/重试」）已经让用户能立刻接着写。
  ⇒ 请用户点头要不要改；要改我就单独一轮做，配一组"慢写 / 复读 / 正常"三种形状的回归。

**联网查过的专业口径**（按本轮"动手前先查技术资料"的长期要求）：业界判"复读/退化"用的是**内容层信号**，不是**数量层信号** ——
distinct-n（唯一 n-gram 占比，Li et al. 2016）与 Self-BLEU（拿自己当参考的 leave-one-out BLEU，Zhu et al. 2018）是标准度量；
2025 年的代码生成重复性研究同样按 **n-gram 重复率**随 n 增大趋零来判"真重复"，agent 侧的监控论文（OpenReview "Monitor Degenerative Repetition in LLM Agents"）也是**逐轮监控输出里的 n-gram 重复率**超阈值就断循环。
⇒ 我们现在这条 `段增量 < max(80, 2%·目标)` 是**数量判据**，天生分不清"每段只写 100 字的慢写"与"把同一段贴三遍"；
   要改就该改成**内容判据**：对本次要追加的那一段，算它与文件已有正文的 **n-gram 重合率**（或直接 distinct-4 掉到多少），重合高 ⇒ 复读 ⇒ 叫停；重合低 ⇒ 哪怕只加 100 字也继续催。
   这样 §8.5 那个 436 字误伤与"复读污染交付物"两头都堵住，而且判据和它自己的文案（"写不动了"）终于一致。

### 13.7 真机把"过度保守"也抓出来了（第 44 轮后半 · 三处红与修法）

`verify-r44-token-live` 第一次跑到"预算 = 整条请求"这一层时红了四条，读数很具体：

```
FAIL 视图额度 > 0 且 小于整条预算 ← 视图 0 / 预算 19661
FAIL 这一轮真实发送的 prompt token ≤ 用户设的预算 ← 真实 23211 vs 预算 19661（固定 20522 + 工具 11197）
```

**根因不是"预算算小了"，是"估算把固定开销算大了"**：旧系数（CJK 1.0/字、ASCII 标点 1.0/字）实测是真实分词的 **1.47–1.55 倍**（两条独立读数：`34550/22204`、`34173/23211`）。后果不是"多留点空位"那么客气 —— 32K 窗口的模型上，固定开销一算就吃掉整个预算 ⇒ **视图额度被算成 0** ⇒ 看起来"有界"，实际是让模型失忆。

2. **不许假装装不下**：预算低于实测下限时把**生效预算抬到下限**（`fenPeiYuSuan.shengXiaoTokens`），但抬不过"窗口 ×(1−执行余量)" ⇒ 视图永远不被算成 0。

## 15.2 图片细则（记忆 #5）——用户原话逐条落

- **校准不再跳过带图的轮**：从供应商回读里**扣掉**图片的视觉 token 再校准文字系数（`token.calibrate-image-split`）；估得比整条回读还大才跳过，并说明原因。
