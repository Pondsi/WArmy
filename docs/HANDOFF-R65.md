## 1. 话筒最终音频丢失（用户 27）

专业依据：MDN `MediaRecorder.stop()` 调度最后一次 `dataavailable`，其后触发 `stop`。调用 stop 后立即清空全局录音引用，会丢弃最后一次事件。参考：https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/stop_event 和 https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event 。

源码证据：录音按钮原先 stop 后马上 `yuYinQingLi()`，后者清空 `yuYinZhuangTai`；ondataavailable 和最终转写又依赖该全局引用。另一个缺口是预览转写 busy 时，最终转写直接 return。

已修改：录音回调捕获自己的状态，停止只标记 stopping，不抢先清空；最终音频积累完再转写；预览未完成时排一次最终转写；最终转写完成后清资源；并发点击启动防重入；结果写入前核对录音所属会话，禁止落入另一个会话输入框。

离线行为验证：`node packages/app-shell/scripts/verify-r65-mic-lifecycle.mjs` EXIT=0，7 PASS / 0 FAIL。通过 AST 提取实际产品录音函数，覆盖短录音最后一块、预览阻塞时最终转写排队、会话切换隔离、并发启动/停止、失败资源释放、自检不改草稿，并恢复“stop后马上清空”错误作为负向对照。这里只证明生命周期，不代替真实音频/供应商链路验收。

执行过程样式同步改在两份CSS：浮雕挂到details容器而非summary，使展开内容在同一边框中；主窗和nm吸附/置顶激活不保留灰底；nm磁铁改CSS mask currentColor，主进程传入ink/主题mode。实际浏览器像素验证待统一启动，不能仅凭源码判通过。

## 2. 微信协议诊断与修复（用户 12）

只读研究发现：适配器把文本类型当作字符串 text 并读 content，而公开 iLink 类型为数值 1 / text_item.text；发送结构、ret 错误校验、实例连接键也有不一致。已落地的修复：

- **文本解析兼容**：`text_item.text` / `text` / `content` / `wenBen` 四种来源都读；`type` 允许数字或字符串；`item_list` 为空时读顶层正文；非文本与未知类型如实提示"读不了内容"，不静默丢。
- **回复发得出去**：不再因缺 `context_token` 直接拒绝——收件人 `to_user_id` 已明确；有 token 时仍校验它属于本会话（防串会话），没有就按纯收件人发；`message_type:2` / `message_state:2` / `client_id` 保留，`ret`/`errcode` 如实校验。
- **忙态收尾**：根因是主进程统一入口 `zhenZhengFaSong` 只广播 `kai:true`，从不广播 `kai:false`；微信/定时这类主进程直派的轮没有渲染层 `deliver().finally` 收尾，界面"干活中"永亮。现在统一在 `finally` 广播 `kai:false`（续派接着跑时延后，避免闪一下）。
- **身份串台**：入站仍只映射到配置里指定的实例/会话，不把任意本机会话回复发给微信联系人。

尚未证明：真实微信端是否可见必须以端到端回执/受控测试对话为准；本机无法替腾讯灰度与协议版本作保证。

## 5. 需要用户拍板/协助

1. **P0-5 自托管凭证**：方案 A 本机自动解锁（体验好，机器被接管即失守）；B 口令+安全存储（更安全，忘记口令需重置）；C 硬件密钥（最强，成本/兼容差）。最坏情况：A 被同机恶意进程读走；B 口令弱可被离线猜解；C 丢失密钥无法恢复。
2. **P0-6 历史重扫/白名单**：全量重扫（彻底，耗时且可能改写历史）；只扫新增（安全，旧泄漏仍在）；白名单自动+审计+撤销（平衡，需定期复核）。最坏情况：选"只扫新增"会把已知泄漏留在旧记录里。
3. **真实微信端到端**：需要用户提供已灰度 ClawBot 的微信、扫码并在手机端发一条受控测试消息；本机只能证明协议夹具，不能证明腾讯侧可见。
4. **网络多服务器默认值**：默认不配服务器（隐私最好，首次联系需手动配网）；或预置一个官方服务器（开箱即用，但元数据外流）。最坏情况：预置官方服务器等于默认把"谁在何时找谁"交给第三方。
5. **附加文本开关默认值**：默认开（便于识别来源，但每条消息多 100 字与一次服务商信任判断）；默认关（最干净，但恶意服务商更难识别）。最坏情况：默认开时，恶意服务商可借附加文本做社会工程；默认关时，伪造来源只能靠签名与指纹，发现更晚。
