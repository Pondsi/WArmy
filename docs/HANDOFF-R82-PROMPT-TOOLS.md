# 交接：#109 提示词校对 / 备份 diff / 回滚

## 是什么

设置→功能新增「提示词校对与回滚」卡，覆盖五层：道、术、教条、束缚、印象。

- **本地校对**：检查空值、超上限、重复行；不联网。
- **备份**：每次覆盖前自动留最近 5 份 `.bak-<时间戳>`。
- **diff**：选择一份备份，按行显示 `+ / -` 差异。
- **回滚**：用备份覆盖当前文件；覆盖前会把当前内容再备份一份。

## 有什么用

- 用户/模型自动改写提示词后，能看出改了什么；
- 改坏了能一键回到上一版；
- 不依赖网络和模型，离线也能检查明显问题；
- 避免“存进去的是半截、界面还显示完整”的旧问题。

## 入口

设置 → 功能 → 提示词校对与回滚。

## 数据与权限

- 文件：`userData/dao.md`、`shu.md`、`agents.md`、`Memory.md`、`yinxiang.md`；
- 备份：同目录 `*.bak-<毫秒时间戳>`，每个文件最多 5 份；
- 回滚只写本机文件，不上传、不联网；IPC 仅主进程可写。

## 方案与取舍

- 方案 A：只保留 CLI 校对脚本。  
  - 优点：零 UI；缺点：普通用户不会用，出问题只能找开发者。
- 方案 B（已采用）：本地确定性校对 + 备份 diff/回滚。  
  - 优点：离线、可逆、成本低；缺点：不做语义校对。
- 方案 C：在设置页直接调 AI 逐条校对并展示 diff。  
  - 优点：能改措辞；缺点：需要密钥/网络、可能改坏语义、要人工确认；目前仍走 `proofread-i18n-ai.mjs`。

## 例子

- 模型归档把「印象」改乱：打开设置 → 校对卡 → 选「印象」→ 看最近备份 → diff → 回滚；
- 用户手改「术」超过上限：本地校对显示“超上限”，可直接改短。

## 最坏情况

- 备份被用户手动删除后无法回滚；
- 回滚会把当前内容覆盖（所以先再备份一份）；
- 本地校对只查形式，不保证语义正确。
