# #109 模型逐条校对：它是什么、怎么跑、例子

> 状态：方案 A 已被用户选中，但本轮只做说明与设计，尚未接入自动校对链路。

## 1. 解决什么问题

提示词（道/术、人格、i18n 长文案）由人工或 AI 翻译后，常见四类问题：

1. **专有名词被译走**：`FWArmy` 变成“防火墙军队”、`Ed25519` 变成“爱德华25519”；
2. **占位符被改坏**：`{ming}` / `{model}` / `{n}` 被翻译或删除，运行时直接印出原文或报错；
3. **长度超上限**：英文/法文等比中文长，切语言后道/术超过该语言折算上限，保存被拒；
4. **语义漂移**：把“不保证送达”翻成“保证送达”，把“可能”翻成“一定”。

人工逐条校对 10 种语言 × 几十条长文案，成本高、容易漏。模型逐条校对不是“让模型自由改写”，而是**受限的审校**：只允许改措辞，不允许改键、占位符、结构、专有名词和承诺强度。

## 2. 流程（可回滚）

1. 导出某个语言的 `键 → 原文`（只导出允许校对的键，白名单）。
2. 按语言分批（建议每批 ≤ 20 条、总输入 ≤ 30k 字符）调用模型，要求返回**同键 JSON**。
3. 机器校验（任何一条不过就整批不写）：
   - 键集合完全一致，不许新增/删除/改名；
   - 占位符集合与原文完全一致（`{ming}`、`{model}`、`{n}`…）；
   - 不许出现原文没有的 HTML/标签；
   - 长度不超过 `shangXianOf(层, 语言)`；
   - 专有名词白名单（WArmy、FWArmy、Ollama、GitHub、Ed25519、BIP-39…）必须原样出现；
   - 联系方式/URL 逐字一致。
4. 人工抽检（建议抽 10%，重点看免责、隐私、权限、计费）。
5. 写回并跑 `verify-i18n-locales`、`verify-r81-ui`、提示词限长门禁；保留原文 diff，一键回滚。

## 3. 例子

### 例 1：占位符
原文（中文）：`你是「{ming}」，运行在「{model}」上。`
模型错误输出（法文）：`Vous êtes « {nom} », exécuté sur « {modèle} ».`
→ 校验发现 `{ming}`/`{model}` 丢失，整批拒绝，**不写回**。

### 例 2：专有名词
原文：`FWArmy 只转发端到端加密的信封。`
模型错误输出：`Firewall Army ne transmet que des enveloppes chiffrées.`
→ 白名单发现 `FWArmy` 被替换，拒绝。

### 例 3：承诺强度
原文：`不保证送达、不保证实时、不保证不丢消息。`
模型错误输出：`La livraison est garantie en temps réel.`
→ 语义校验（关键词对：guarantee/garantie 与“不保证”冲突）报警，人工复核后拒绝。

### 例 4：长度
英文道 7949 字符，英文上限 9750，合法；法文系数 4 ⇒ 上限 10400。模型把法文道改到 11000 ⇒ 拒绝，保留旧版并提示“需要压缩/重译”。

### 例 5：正常校对
原文（俄文，机器直译）：`Программа является локально-первой.`
模型校对：`Программа работает преимущественно локально.`
→ 键/占位符/长度/专名都通过，写入；diff 只改这一句。

## 4. 成本与风险

- 成本：按语言分批，一次全量约 8 语言 × 若干批；模型费用由用户承担，建议只在校对时跑，不随每次启动跑。
- 最大风险：模型“顺手改好”却改错法律含义。因此：白名单键、结构守恒、人工抽检、原文 diff、一键回滚，四者缺一不可。
- 不让模型碰的键：代码标识、IPC 名、审计事件名、协议字段、许可证正文。

## 5. 落地顺序（建议）

1. 先接 `verify-prompt-proofread.mjs`（纯函数校验：键/占位符/长度/专名/联系方式）；
2. 再接模型批处理脚本（只读导出 → 校验 → 写回，默认 dry-run）；
3. 最后接设置页“校对当前语言”按钮 + diff 查看/回滚。
