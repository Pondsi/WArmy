> 未 commit、未 push。本轮只改了引导的推进方式与卡片位置，并补了测试。

## 1. 调研结论（2026）

参考：
- NN/g《Instructional Overlays and Coach Marks》：提示要短、一次只教一个动作、必须可关闭。
- Userpilot / Docsie / Appstorys（2026）：progressive disclosure + checklist；coach mark 只在“下一步不明显”时使用；必须有明确主按钮与跳过。
- Bolderapps（2026）：onboarding = progressive disclosure + permission priming + activation，不靠自动巡检替用户做决定。

结论：上一版引导的问题不是“高亮不亮”，而是**自动巡检每 300ms 替用户跳步**，加上卡片追着目标移动，用户点按钮时卡片已经换位置/换步骤，表现为“点了设置后卡住/乱跳/点不到下一步”。

## 2. 新版引导（确定性步骤）

- **不再自动跳步**：巡检器只同步高亮，推进只由用户点「下一步 / 去操作」触发。
- **卡片固定右下角**：不再追着目标移动，按钮坐标稳定；目标用 spotlight 洞标出。
- 7 步，覆盖“能开始对话并让牛马干活”：
  1. 打开设置（去设置）；
  2. 打开模型分区（下一步校验 `state.nav=settings && settingsSection=model`）；
  3. 添加供应商（有 provider 才可下一步）；
  4. 填密钥（有 key 才可下一步）；
  5. 拉取模型（有 models 才可下一步）；
  6. 创建牛马（有 instance 才可下一步）；
  7. 打开聊天（打开第一只牛马，完成）。
- 「下一步」会执行 `check || done`；未达成时把 pending 文案写进卡片，不推进、不假装完成。
- 「跳过」随时可用；跳过只记 `guideDone`，功能不受限；之后可在「设置 → 关于 → 重新打开首次引导卡」重看。
- 重放强制回第 1 步并停住（上一轮已有，本轮保留）。
- 引导跳转失败会写 `window.__yinDaoActionError` 并 `console.error`，不再静默。

验证：`verify-r78-auth-tour` **47/0**（含：去设置→下一步→模型→下一步→供应商；直接点设置/模型也能前进；重看停在第 1 步）。

## 3. 仍完全未完成（按你的要求逐项说明）

### #106 会话路由 B

- **是什么**：发送前按会话选路、失败重试、全部失败时会话只读并广播“网络不可用”。
- **有什么用**：多服务器/多网络下消息真的送到；断网时如实显示“未送达”，不写假绿勾。
- **方案**：
  - B1 先接 mesh 聊天通道：局域网可用、改动小；公网仍需中继。
  - B2 先接 FWArmy 中继：公网可用；要写中继客户端、outbox、回执、重试。
- **优点/缺点**：B1 快但只覆盖局域网；B2 完整但要处理重试/去重/顺序。
- **例子**：A 服务器挂了自动切 B；全挂时消息留待发、界面显示“未送达”。
- **最坏**：只做发送不做回执 ⇒ 用户以为发出去了、对端没收到；只做选路不做 outbox ⇒ 重启丢待发。

### #108 角色矩阵 + 审批 + Ed25519 锚点 B

- **是什么**：creator/admin/member 权限、加入审批、成员证书、邀请名片 QR、每会话稳定锚点。
- **有什么用**：多人协作时权限不被越权；换网络/换服务器后仍能确认“还是同一个会话”。
- **方案**：每会话 Ed25519 密钥对，公钥指纹做锚点，私钥本机安全存储；名片带指纹+一次性 token；消息/证书签名；旧邀请由创建者 `supersedes` 失效。
- **优点/缺点**：可验签、换网不变、离线可验；私钥丢失=会话身份丢失，必须随身份备份。
- **例子**：换 Wi-Fi 后对方仍用同一指纹验签，不认错会话。
- **最坏**：随机 ID 不验签 ⇒ 恶意中继可冒充；锚点私钥不备份 ⇒ 换机后老会话无法继续。

### #112 项目/群/联系人「查看」弹窗

- **是什么**：查看名称/头像/成员/网络/申请名单/权限；创建者可改名/解散；成员可退出；联系人可查看备注/邮箱/签名/加入时间/删除。
- **现状**：基础查看弹窗已做；加入申请名单目前只显示本机最近 30 天申请，**没有服务端 incoming 申请存储**；邀请二维码/链接没有放进这个弹窗（复用现有加入页）。
- **方案**：完整版需要新增 `joinApplications` 存储（按 groupId、30 天、同意/拒绝/拉黑）并在弹窗里审批；邀请卡直接复用现有 `inviteCreate`/`qrSvg`。
- **最坏**：没有服务端申请存储 ⇒ 只能看到本机发起过的申请，看不到别人申请加入；不能假装有。

### #103 用户切换 + 归档自动归纳规范

- **是什么**：第四列知识库按会话保存可读/可写/可归档；在线用户切换只展示公开层；归档时按会话类型自动归纳规范。
- **现状**：知识库搜索重构/删除已做；`kbLayersFor`/`kbWriteLayers` 已有默认矩阵；**第四列三勾选 UI、在线用户切换、归档归纳规范未接完**。
- **方案**：AF 前端勾选 + 后端写权限复核；BF 先只做“本机牛马可写三层、共享会话只写会话层”，再加用户切换。
- **最坏**：只信前端勾选 ⇒ 私密层越权；默认值写错 ⇒ 群成员能写内部库。

### #113/#115 接入向导 + 连通性检测
