审计日期：2026-10-29。对象：当前本地工作树，包含尚未提交的改动；不是仅审阅旧提交，也不代表已发布安装包的全部状态。

## 0. 先给结论

**项目已经有相当完整的产品骨架和大量真实能力，但还不能认定“全部完成、只剩用户配合”。**最大的短板不是缺少更多按钮，而是跨模块契约、失败时的数据保护、权限一致性和验收可信度。继续只加功能或重复跑原有绿门禁，会把这些问题留到实际使用时才暴露。

推荐主线：**先保护现有数据、修正验收判分 → 修复通信和执行权限 → 消除重复 I/O 与渲染 → 完成已选存储架构 → 补功能闭环 → 打磨体验 → 对最终候选包重新做完整十轮。**性能优先，不等于为了跑分牺牲数据完整性或把权限检查关闭；先排除会丢数据、会把数据送错人的问题，之后工程投入以性能为主。

本次已经做了源代码审阅、官方资料对照、开源实现对照，以及少量隔离行为试验。**没有修改产品代码，没有调用新的模型，没有读取真实密钥或真实用户数据，没有发布、安装或重置真实配置。**下文的改进均是待实施路线，不是已经修好的声明。

- **实测复现**：本次在独立临时目录、假密钥、合成数据上运行了当前源码，得到可重复的问题输出。

## 3. 第一优先级：数据完整性与恢复

### D1｜P0，实测复现：封存成功后不能恢复，源文件已删除

证据：[data-vault.ts:190](../packages/app-shell/src/data-vault.ts#L190)、[归档写入:245](../packages/app-shell/src/data-vault.ts#L245)、[封存提交:954](../packages/app-shell/src/data-vault.ts#L954)，以及 [enc-fs.cjs:944](../packages/app-shell/src/enc-fs.cjs#L944)。

- 清单使用 `lstatSync().size`，得到密文物理长度；正文使用包装后的 `createReadStream`，输出明文逻辑内容。
- 本次合成文件：`lstat=75`、`stat=26`、流读取 `26` 字节。归档条目声明长度与实际内容不一致。
- 联合测试得到：`seal.ok=true`，两个文件合计逻辑内容 60 字节，源设置文件已不存在；随后 `unseal.ok=false`，错误为 `bad-archive（路径过长）`，设置文件未恢复。
- 这是当前源码组合后的真实错误，不是模型能力、网络或缺第二台设备。

**修法：**保持 `lstat` 用于禁止符号链接，另通过统一存储 API 取得逻辑长度；逐条核对实际写入字节数；源数据版本在读取期间变化则失败或重做一致性快照；候选归档完成认证和结构校验后才提交并删除工作副本。流式校验增加一次顺序读取的代价，换来不删除唯一可恢复数据；后续通过事务快照减少重复工作。

**验收：**普通文件、JSONL、TYPE_STREAM、多文件、中文路径、空文件均做 enc-fs＋DataVault 联合往返；篡改、截断、写失败、并发修改时保留源数据。先通过这一组，才允许触碰真实 profile 的封存/重置交付。

### D2｜P0，实测复现：JSONL 读取错误被当成不存在，追加覆盖旧内容

证据：[enc-fs.cjs:213](../packages/app-shell/src/enc-fs.cjs#L213)。

`appendLogical()` 捕获所有读取错误后继续把旧内容当空。隔离试验注入一次 `EIO`：追加没有抛错，文件从 **1,048,692 字节变成 74 字节**，旧数据未保留。

**修法：**只有 `ENOENT` 可以进入新建分支；权限、I/O、格式、密钥或认证错误一律不写原文件并显式失败。正常密文追加只读固定头和必要尾部，不能先读完整文件；旧明文转换单独流式迁移。记录写入和头计数更新之间的崩溃恢复规则也要明确，不能仅靠“写完头”代表成功。

**验收：**读取故障前后哈希不变；合法新建、已有文件追加均正确；追加中断可发现和恢复尾部不完整记录，不静默承认截断内容。

### D3｜P1，静态确认：加密记忆事实和原生 fd 索引读取不兼容

证据：[memory-os/index.ts:1332](../packages/memory-os/src/index.ts#L1332)、[投影重建:1349](../packages/memory-os/src/index.ts#L1349)、[逐行读取:1531](../packages/memory-os/src/index.ts#L1531)。

原文回读、行迭代和部分索引构建仍使用 `openSync/readSync`，而 enc-fs 没有把这些 fd 接口变成逻辑解密读取。本次最小探针确认原生 fd 读到 `WARMYEF2`，不是 JSONL；完整记忆服务重建尚未在本次运行。

**修法：**提供显式逻辑记录迭代和按记录取原文接口；密文物理偏移、明文字节偏移、seq 三种概念分开，建立记录级位置索引。重建新投影成功后再原子替换旧投影，不能先清空可用投影再尝试解析。

**验收：**加密写入→全文读取→关闭重开→丢弃临时投影后重建；长文本尾部、中文、跨记录分页的哈希一致，不能靠预览文字勉强回答当通过。

### D4｜P1，静态确认：外部编辑回写失败也清掉唯一新副本

证据：[external-edit.ts:184](../packages/app-shell/src/external-edit.ts#L184)。`finishNow()` 的 `finally` 无论成功失败都删除临时副本及清单；大文件还被一次性读入内存。文件占用、磁盘满或 rename 失败时，可能丢掉新编辑结果。

**修法：**仅成功提交或明确丢弃才清理；失败进入可重试恢复态，保留副本和清单；注销/退出收集失败结果，不假报全部封存成功；比对原文件版本，避免覆盖并发编辑。受管恢复副本默认保持加密，外部编辑的明文期仍按已批准会话边界处理。

**验收：**注入写/rename 失败、原文件被并发更改、进程重启；旧原件与新编辑均可找回。Office 的真实锁文件和自动保存行为作为额外环境验收。

### D5｜P1，静态风险：归档输出流失败未反向终止全部等待

证据：[data-vault.ts:224](../packages/app-shell/src/data-vault.ts#L224)。输出流错误仅拒绝一个稍后才等待的 Promise，生产者可能仍等待 gzip 的 `drain`/流结束。

**修法：**统一 `pipeline`/取消信号和错误收敛；任一阶段失败就终止整链、唤醒等待、保留源文件并移除本次候选输出。

**验收：**本地故障 Writable 在中途失败时任务在规定上限内返回，所有流关闭；不能靠延长超时掩盖挂起。

### 4.1 命令隔离如何兼顾性能与自主性

不建议一上来强制所有用户安装 Docker，也不建议用“已弹授权卡”代替执行隔离。

1. 先统一授权入口，修 cwd 与自定义工具旁路，保留已定授权语义。
2. 对本机执行建立最小环境变量白名单、超时、输出上限、进程树清理；不得向普通工具进程发放全局 DEK。
3. Windows Job Object 用于进程树与资源控制，**它本身不是文件系统权限沙箱**。要限制文件/网络访问，需要受限令牌、AppContainer 或其他适配的 OS 能力并做兼容验证。
4. 文件读写优先走范围明确的工具 API。必须运行任意脚本时，明确区分“受控工作区执行”与“已授权宿主执行”，不悄悄升级。
5. 利用已有本机隔离能力做测试；缺能力时保留拒绝/需现有授权状态，不自动安装特权组件、不降低安全下限来伪造全自动。

### 5.1 建议的性能验收指标

先测现状，再冻结参考机器、数据集和指标阈值。以下是**建议目标，不是已经达到或已经证实超标**：

- 常用本地点击到反馈 p95 ≤100ms，长任务启动/取消在 200ms 内出现状态反馈；网络和模型推理时间另计。
- 聊天出字期间不重建未变化的历史过程节点；输入、选区和滚动不被抢。
- 常见本地交互主线程尽量无超过 50ms 的长任务；导入/索引建立期间仍可取消和查看进度。
- 正常 JSONL 追加读取量不随历史体积线性增长；流式复制增大文件时峰值内存保持近似有界。
- 1,000/10,000/100,000 条合成历史分别测首次打开、翻页、全文回读、召回；报告 p50/p95/p99，不能只报平均值。
- 30–60 分钟空闲/开关窗口/切换会话试验后，已释放资源不得持续增长；缓存有总字节预算，非仅条目数上限。
- 同机同数据对比优化前后：正确性不变，目标热点明显改善，无相关场景超过预先设定的回归容差；噪声用多样本区分，不按单次最优值宣传。
- 模型路径拆成排队、预算装配、召回、请求、首 token、生成、工具、持久化、渲染；避免把 Ollama 冷加载或 MiMo 网络耗时当成 Electron 的性能问题。

### 5.2 不推荐的“优化”

不关闭加密/权限/审计来跑分；不对私密与共享会话复用无作用域缓存；不无条件调高模型轮数、token 或并发；不把所有重活同时并行压满本机；不为速度把数据持久性改成 `synchronous=OFF`。

SQLite WAL 仍是单写者；`NORMAL` 与 `FULL` 的断电耐久性不同。优先批量事务、减少写入和可控 checkpoint，不静默把丢最近提交事务当作性能优化。

- **所有阻塞有明确状态和下一步。**区分排队、等待授权、连接、运行、部分完成、已停止、失败、已送出、已收件，避免一个“成功”覆盖多种含义。
- **长操作可取消、可恢复。**导入、导出、索引、下载和外部编辑状态共用一致文案/进度原则；失败说明是否保留原件和如何恢复，不输出纯堆栈给用户。
- **统一视觉变量。**字体、字号层级、间距、圆角、边线、主题色、焦点、disabled/loading 使用现有 CSS token；不在此阶段更换 UI 框架或重做已选首启风格。
- **动态效果有资源纪律。**[首启 engine.js:940](../packages/app-shell/src/renderer/firstrun-scenes/engine.js#L940) 连续 requestAnimationFrame，未见 reduced-motion 处理；退出确认动画已有相应处理，不代表首启 canvas 也有。为 canvas 补减少动态效果静态帧，核对隐藏/最小化状态；不能仅凭代码说后台一定高 CPU，要实际量测。

### 8.2 国际化不能只验语言包键齐

[即时记忆入口:18621](../packages/app-shell/src/electron-main.ts#L18621) 的长期措辞正则主要是中文。英文等“请记住”是否进入相同能力，需语言语义夹具，而不是只看界面已翻译。

新增验收：十语言同功能入口、长名称截断、占位符替换、IANA 时区/日期、数字和单位、键盘/读屏标签；错误状态和帮助文案都要覆盖。长期记忆捕捉先用受控语言表达及用户明确意图规则，不为翻译每条消息额外调用分类模型，避免增加常规聊天延迟。

### 8.3 应新增的工程能力，而非盲加产品功能

1. **恢复演练**：备份任务成功标准包含可验证 manifest/完整性；定期对合成仓做恢复测试，真实仓不自动破坏性演练。
2. **本地性能诊断**：结构化阶段耗时、队列长度、事件循环延迟、缓存命中、写入字节；默认不记聊天正文/密钥，不增加云遥测。
3. **操作幂等与恢复台账**：发消息、写文件、创建任务、外部编辑分别有 operationId 和提交状态；重启不重复制造副作用。
4. **依赖与运行时维护**：锁定依赖、SBOM、许可证和本地依赖漏洞扫描流程；检查数据库实际 cipher/ABI，自检失败明确报错。未跑漏洞扫描时不说“依赖安全”。
5. **构建证据绑定**：同一版本号不等于同一包；实际运行模块与最终安装包摘要必须可查。
6. **测试仪器自检与变异测试**：缺 DOM、坏返回码、少一条结果、假成功、被吞异常、未变化产物都必须能让验收变红。

- 真模型只使用 MiMo/Ollama；每轮记录实际调用、模型、响应与 usage，不能改用 DeepSeek 或其他供应商。

- 桌面试验串行，避免共享桌面互抢焦点；独立 Node 测试可有界并行。
- 缓存依赖与构建，不把缓存的测试结果冒充新一轮执行。不同轮换 seed、数据和输入路径，不只是换一个暗号。

- 成功后仅保留脱敏摘要、哈希、必要截图/小型重放夹具；完整真实 profile 和密钥绝不进证据包。临时数据按任务归属清理。
