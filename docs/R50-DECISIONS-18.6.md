# §18.6 十一条设计取向 · 决策说明书

> 对应 HANDOFF-R44 §18.6。每条：**要你定什么 / 起什么作用 / 推荐 / 优缺点 / 可能情况 / 最坏情况**。
> 推荐默认按「日常可用 + 可回退」写；标 ★ 的是强烈建议先定的。

---

## ★1. 定向模式（仅 @ai 才发言）

| 项 | 内容 |
|---|---|
| **要你定什么** | 群里「只有 @我 才说话」时，@名字 → 哪只牛马实例？按名片、按 id、还是群管理员绑定？ |
| **作用** | 多牛马同群时避免全员抢话；被点名的才接单。 |
| **推荐** | 群设置里显式绑定：`@显示名 → 实例`；未绑定的 @ 忽略并提示。禁止靠猜。 |
| **优点** | 可预期、可审计、不误触发。 |
| **缺点** | 要配一次；改名要同步。 |
| **可能情况** | @错人 → 明确说「没绑这个」；多人同时 @ → 按消息顺序排队。 |
| **最坏** | 未绑定就全员沉默（现状）或全员抢答刷屏。绑定表可导出备份。 |

## ★2. 社交消息进哪条会话（作用域）

| 项 | 内容 |
|---|---|
| **要你定什么** | 微信/外部联系人的话：进你**主会话**，还是**每联系人/每群单独会话**？全局召回对他们可见吗？ |
| **作用** | 防止外部人套出你在别处说过的话；也决定记忆要不要隔离。 |
| **推荐** | **默认每外部群/人独立会话** + 记忆作用域=该会话+项目（禁止全局）。主会话只收你自己的话。可对「信任联系人」开白名单进主会话。 |
| **优点** | 隐私安全（业界默认）；可单独设提示词/模型。 |
| **缺点** | 会话变多；跨会话总结要另做。 |
| **可能情况** | 外部人问「你老板说过什么」→ 不可见；你主动转述则可见。 |
| **最坏** | 若保持现状：外部人可全局 recall 套话（**隐私事故**）。 |

## 3. 执行者预算：固定上限 vs 按窗口计价

| 项 | 内容 |
|---|---|
| **要你定什么** | 多执行者用小窗口模型（8K/16K）时，毯/摘要超窗怎么办。 |
| **作用** | 控制一次任务发给子执行者的上下文大小。 |
| **推荐** | **按窗口计价**（与主请求同一套 `peizhiYuSuan`），超窗自动收缩毯再试一次；仍超再如实 `CONTEXT_OVERFLOW`。 |
| **优点** | 小模型也能跑；与预算体系一致。 |
| **缺点** | 实现多一层收缩；极端任务信息变少。 |
| **可能情况** | 8K 模型 + 长任务 → 自动变短毯，执行者只看摘要+指针。 |
| **最坏** | 现状：小窗模型首轮就炸且不重试 → 任务卡死。 |

## 4. 多执行者：并行 vs 接力

| 项 | 内容 |
|---|---|
| **要你定什么** | 开工时同时起跑，还是 A 做完 B 再做？ |
| **作用** | 黑板（共享事实）何时有内容可读。 |
| **推荐** | 默认**并行** + 开工写「目标/边界」到黑板；可选「接力」模式给有依赖的步骤。 |
| **优点** | 快；黑板仍是唯一事实源。 |
| **缺点** | 并行时黑板开局空，需 `heiban_read`；可能重复劳动。 |
| **可能情况** | 两人写同一文件 → 黑板冲突条目交人裁决（已有）。 |
| **最坏** | 纯并行+无开局广播 → 重复造轮子；纯接力 → 慢一倍。 |

## 5. 跨轮是否自动带回上一轮黑板

| 项 | 内容 |
|---|---|
| **要你定什么** | 新一轮「继续做上次那个」时，自动注入上次黑板，还是必须 `recall`？ |
| **作用** | 长任务连续性的成本 vs 噪声。 |
| **推荐** | **同一计划/同一用户话题**自动带**有界摘要**（≤2400 字）+ 指针；跨任务不带。 |
| **优点** | 「接着做」不用你复述。 |
| **缺点** | 可能把无关旧事带进新任务。 |
| **可能情况** | 明确新任务 → 不带；「继续」→ 带摘要。 |
| **最坏** | 全带：上下文膨胀；全不带：每次从零解释。 |

## 6. 窗口不明时两处兜底不一致

| 项 | 内容 |
|---|---|
| **要你定什么** | 预算用 32768 保守，额度窗显示 128K —— 统一成哪一个？ |
| **作用** | 避免「账单/额度」与「实际发出去的」两套数。 |
| **推荐** | **统一保守 32768**；界面标注「窗口未知，按 32K 估算」。用户可手动填窗口覆盖。 |
| **优点** | 不会超窗扣费/失败；数字一致。 |
| **缺点** | 未知窗口的大模型被低估，显得「额度少」。 |
| **可能情况** | 拉到真实窗口后自动改为实值（#15 已做）。 |
| **最坏** | 保持双轨：用户对不上账、以为被多扣。 |

## ★7. 中间回复要不要进记忆库

| 项 | 内容 |
|---|---|
| **要你定什么** | 流式中间回复/「执行过程」要不要 `recall` 得到、要不要算记忆条数。 |
| **作用** | 「我刚才说到一半的那句」能否被找回；日志条数=记忆条数是否守恒。 |
| **推荐** | **进旁路日志 + 一条压缩摘要记忆**（「本轮说过 X」），**不算**完整消息记忆条数；最终回复才进正文记忆。 |
| **优点** | 可追溯；不污染正式记忆；条数例外可审计。 |
| **缺点** | 多一种记录类型；实现要打标。 |
| **可能情况** | 被打断 → 中间内容仍可 recall；正式结论以最终回复为准。 |
| **最坏** | 全进记忆：噪声大、重复；全不进：中断后「说了像没说」。 |

## 8. 「道」约 14312 token 占窗

| 项 | 内容 |
|---|---|
| **要你定什么** | 32K 本地模型上，是否提供「精简道」配置档（你规则是不可压缩，故只能**你选精简稿**）。 |
| **作用** | 留出更多对话空间。 |
| **推荐** | 保持完整出厂稿；另设**可选精简档**（你亲自审定的 3–4K 稿），设置里切换，默认完整。 |
| **优点** | 小模型可用；不破坏「不可自动压缩」。 |
| **缺点** | 两套文案要你维护。 |
| **可能情况** | 本地 27B + 完整道 → 对话约剩 17K；精简档 → 约剩 28K。 |
| **最坏** | 只留完整：小模型长任务易顶窗；只留精简：底线表述变薄。 |

## 9. ASR 路由（本机优先）

| 项 | 内容 |
|---|---|
| **要你定什么** | 是否按已定稿执行；话筒自检数值是否现在取。 |
| **作用** | 语音识别：本机快/私密，云准/兜底；重试不丢音频。 |
| **推荐** | **按定稿做**；先跑话筒自检脚本取数值再改代码。 |
| **优点** | 离线可用；隐私好。 |
| **缺点** | 本机识别质量看硬件/模型。 |
| **可能情况** | 本机失败 → 落云链（三种情况已定稿）；云失败 → 如实报，不丢录音。 |
| **最坏** | 不做：语音全靠云，断网即废；乱做：重试丢音频。 |

## 10. 字数停滞阈值

| 项 | 内容 |
|---|---|
| **要你定什么** | 继续用「段增量数量」判停滞，还是改成内容信号（distinct-n / Self-BLEU）？ |
| **作用** | 判「模型在复读/卡住」以便续派或中断。 |
| **推荐** | **内容信号**（复读率高=停滞）+ 保留数量判据作辅助；配「慢写/复读/正常」三形状回归。 |
| **优点** | 少误伤慢写；能抓住真复读。 |
| **缺点** | 算法略重；要样本。 |
| **可能情况** | 每段 100 字慢写 → 不误判；整段复制 → 判停。 |
| **最坏** | 只看数量：436 字那次误杀；只看内容：极慢真卡住可能漏。 |

## 11. dsh 控制消息未 import 契约类型

| 项 | 内容 |
|---|---|
| **要你定什么** | 是否按契约 `AcpKongzhiXiaoxi` 补齐 import（偏工程债，产品行为影响小）。 |
| **作用** | 类型一致、防字段漂移。 |
| **推荐** | **补上**，门禁钉住「dsh 侧与 memory-client 同一契约」。 |
| **优点** | 改契约时编译期抓错。 |
| **缺点** | 纯工程时间。 |
| **可能情况** | 不补：字段改名时运行时才炸。 |
| **最坏** | 不补：控制消息静默丢字段。 |
