## 一、先回答：P0–P3 是什么？

**P0–P3 是“消息插入 / 排队”的紧急度，不是重要程度。**

| 级别 | 界面含义 | 行为 |
|---|---|---|
| P0 | 停止 | 停止当前 AI / 清空正在跑的任务 |
| P1 | 加急 | 打断当前活、立即插入派发（要二次确认） |
| P2 | 插入 | 默认；正常插入当前会话 |
| P3 | 排队 | 不插队；进入待执行队列 |

- 只影响**消息怎么投递、要不要插队、队列怎么排**。
- **不影响选哪个模型，也不影响思考强度。**
- **难易 + 杂简**是另一套分诊器（`panDuanZhongYaoFuZa`），只在**智能模式**或**思考级别=自然（自动）**时调用；
  难→模型档，杂→思考档，急/缓只影响投递。

## 二、两条路径：智能模式 vs 严格链

牛马设置里的「调用链 → 智能模式」复选框（`iSmartMoXing`）决定走哪条。

### 2.1 勾选「智能模式」

**难易（nan）决定模型档，杂简（za）决定思考档**（详见 [`DIFFICULTY-NANZA-R98.md`](./DIFFICULTY-NANZA-R98.md)）：

| 分类结果 | 模型选择 | 思考级别（仅当牛马=自然/自动） |
|---|---|---|
| `modelTier=high`（nan≥4） | 链上**第一个非本地**（云端强模型）；没有云端才退回链头 | 由 za + 顶模型提升决定 |
| `modelTier=mid`（nan=3） | **链头**（链上第一个启用且可用） | 由 za + 顶模型提升决定 |
| `modelTier=low`（nan≤2） | 链上**第一个本地/免费**；没有本地才退回链头 | 由 za 决定（通常 off/low/medium） |

- 智能模式**不把默认模型当硬指定**；默认模型字段在勾选时被清空（`__smart__`）。
- 链位仍然遵守：跳过被禁用、供应商里不存在、本轮已失败、全局对话白名单外的模型。
- 分类器不可用时：本地启发式分别估 nan/za（不把步数当难度、不把难度当步数）；
  若连启发式也没有（不会发生，函数总返回），按 `mid`/`medium`。

### 2.2 未勾选「智能模式」（严格链）

1. 消息显式指定的模型（用户在消息里手动选）—— 最高优先；
2. **牛马默认模型** —— 先试它；
3. 默认模型不行（不存在 / 被禁用 / 没密钥 / 调用失败 / 本轮已失败）⇒
   **严格按调用链配置顺序，从第 1 个开始逐个试**：
   - 跳过被禁用的；
   - 跳过供应商里不存在的；
   - 跳过本轮已经失败的；
   - 不按 P0–P3、不按“云端/本地/免费”、不按“链头/链尾”做任何跳位。
4. 链为空或都不可用 ⇒ 角色表**固定顺序**：duty → executor → summary；
5. 仍没有 ⇒ 任意真实可用模型 ⇒ 最终兜底。

> 严格链路径**不把默认模型当“链外特例”跳过**：默认模型先试一次，失败后才从链头开始
> （若默认模型也在链里，会因“本轮已失败”被自然跳过）。

### 2.3 思考级别

- 牛马思考级别**不是**「自然（自动）」⇒ **严格用用户选的档位**，分类器不参与思考级别；
- 是「自然（自动）」⇒ 用分类器的 `thinkLevel`；
- 分类器也没有 ⇒ 固定中档 0.5（不再被 P0/P1 抬高、P3 压低）。

**省调用**：非智能模式 + 用户已选具体思考档 ⇒ **完全不调用分类器**（模型按严格链、思考按用户档）。

### 2.4 难易/杂简折算（防“无脑 high/high”）

`panDuanNanZa`：

- 模型档只看 **nan**：`nan≥4`→high、`3`→mid、`≤2`→low；**不被 za 改变**。
- 思考档先看 **za**：`≥4`→high、`3`→medium、`2`→low、`≤1`→off。
- **顶模型仍可能失手**：`nan≥5` / `nan≥4 且置信<0.6` / `nan≥4 且 importance≥4` ⇒ 思考抬到 high；
  难任务（nan≥4）思考至少 medium。
- **急/缓不改模型和思考**：P0/P1 只改投递/插话；同一 nan/za 下急与缓的 modelTier/thinkLevel 必须相同。
- 3 分在八组合里归“易/简”，但仍得到 mid 模型 / medium 思考，不是无成本。

## 三、例子（真机/真值表验证过的）

| 场景 | 结果 |
|---|---|
| 智能模式，简单「你好」 | 分诊 nan2/za1 ⇒ tier low / think off ⇒ 链上第一个本地 `qwen3.8-27b:iq3-128K`，`why: smart` |
| 智能模式，高风险多步骤任务 | 分诊 nan4/za4 ⇒ tier high / think high ⇒ `deepseek-flash`（链上第一个非本地），`chainIndex 1` |
| 智能模式，难但步骤少 | nan5/za1 ⇒ tier high / think high（顶模型仍可能失手）；模型仍按链位挑 |
| 智能模式，易但步骤杂 | nan2/za5 ⇒ tier low / think high（思考高、模型可以低） |
| 智能模式，链上只有一个本地模型但任务 high | 没有云端可选 ⇒ 退回链头本地模型（不会无模型可用） |
| 非智能，默认 `A`，链 `[B, C]` | `A` 可用 ⇒ `A`；`A` 失败 ⇒ `B` ⇒ `C`，不跳位 |

## 五、历史情况：之前有智能模式吗？漏洞在哪？

**有，但第 97 轮被“严格链”改动实质禁用了。**

- 旧实现（R97）：`P2=链头`、`P3=第一个本地/免费`、`P0/P1=第一个云端`，
  由消息紧急度驱动；用户当时要求“默认模型不行就严格顺链”，于是删除了智能跳位。
- 本轮恢复为**显式勾选**的智能模式，且由“难易度”而非紧急度驱动，才符合最终口径。

本轮审计发现并处理的洞：

1. **全局对话白名单会过滤本地模型**：`specialModels.chatChain` 只勾了云端时，
   智能 low 档选中的本地模型会被 `chat.model-blocked` 拒掉并继续顺链。
   这是产品既有约束（白名单优先），不是路由 bug；真机探针一开始就踩到，
   把本地模型加进白名单后才测出 low 档行为。
2. **群执行者听自己的设置**：`executorConfig` 现在会读该牛马自己的 `smartMode`；
   勾了就用**它自己的**链/本地清单按派发计划的 `modelTier` 选第一个，未勾仍默认→严格链。
   值班者只提供难易度，**不能指定模型**（详见 [`DISPATCH-PLAN-R98.md`](./DISPATCH-PLAN-R98.md)）。
3. **分类器是启发式 + 模型**：本地启发式按长度/步骤/工具词/高风险词估档，
   对“很短但极难”的问题可能低估；分类模型可用时以模型 JSON 为准。
4. **显式思考档与非智能模式**：用户已选档位时分类器完全不调，
   因此模型也不会因“任务简单”被降档——这符合“用户显式优先”，但意味着
   “选了高思考 + 简单任务”仍会花高思考成本。
5. **默认模型与智能模式互斥**：选具体默认模型会取消智能模式（R97 修复）；
   勾智能模式会清空默认模型。不会再出现“默认模型写着 Ollama、实际一直用 MiMo”。
6. **模型能力/供应商不可用**：智能选型只保证“链上、未禁用、在白名单、本轮未失败”，
   不保证该模型当前有额度；额度/404 仍由调用失败后的顺链降级处理。
7. **本地模型判定**：`lieBenDiMoXing()` 按供应商协议（Ollama）与模型清单判断；
   远程自托管的 Ollama 也会被当“本地”，对 low 档是有意为之（免费/低延迟）。

## 七、边界与未做

- 智能模式在**单聊/牛马自身**与**它作为群执行者**时都生效；群执行者用的是它自己的设置，
  值班者只能给难易度，不能改模型（见 [`DISPATCH-PLAN-R98.md`](./DISPATCH-PLAN-R98.md)）。
- 分类器需要一次额外模型调用（可配“分类模型”）；不可用时走本地启发式并审计 `triage.local`。
- 智能模式不会越过全局对话白名单；白名单里没有的模型永远不会被选中。
- 思考档位不支持“该模型没有的档”：`siKaoCanShu` 会映射到模型支持的最接近档；
  模型完全不支持 thinking ⇒ 不发送 thinking 参数（如实降级，不假装）。
- 历史项 R97-2（“智能选型 P2=链头、P3=本地/免费”）已被本定稿取代：
  现在由“智能模式勾选 + 难易度”驱动，**与紧急度彻底解耦**。
