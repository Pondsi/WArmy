# MiMo Desktop 如何保证「记得住、做得完」——机制报告与 WArmy 复用建议

> 依据：本机 Xiaomi MiMo Desktop（内嵌 MiMoCode 引擎）实际文件布局、内置 skill 文档
>（`mimo-desktop-guide` / `mimocode-docs`）、以及本项目长会话中的运行时行为。
> 作者署名见文末。

---

## 一、总览：它用哪些层「托住」项目记忆

```text
┌─────────────────────────────────────────────────────────────┐
│  Desktop UI（会话/项目/Artifacts/计划任务/设置）              │
├─────────────────────────────────────────────────────────────┤
│  引擎会话（system prompt 注入 + 工具调用 + 权限卡）           │
├──────────────┬──────────────┬──────────────┬────────────────┤
│ 持久记忆层    │ 上下文治理层  │ 任务树层      │ 结构化交互层    │
│ MEMORY.md    │ checkpoint   │ task T1/T2   │ question 选项卡 │
│ notes.md     │ compact      │ progress.md  │ 权限确认卡      │
│ progress.md  │ dream/记忆检索│ goal 判停     │ fork 分支会话   │
└──────────────┴──────────────┴──────────────┴────────────────┘
        文件系统 ~/.local/share/mimocode/memory/ + 项目 .mimocode/
```

核心思想：**不指望单次对话窗口装下全部项目，而用「分层事实源 + 可检索恢复 + 显式任务状态」保证目标不丢、步骤不虚。**

## 二、如何确保「始终记得项目要干什么」

### 2.1 多层 Markdown 记忆（磁盘为真）

实测路径（本机）：

| 文件 | 作用 |
|------|------|
| `~/.local/share/mimocode/memory/global/MEMORY.md` | **跨项目**用户偏好、固定工作流（如搜索链、命名定稿） |
| `memory/projects/global/MEMORY.md`（及项目级） | **项目规则 / 架构决策 / 待办队列 / 门禁基线** |
| `memory/sessions/<sid>/notes.md` | 会话自由笔记（引用、未决问题、跨项目观察） |
| `memory/sessions/<sid>/tasks/<TID>/progress.md` | 绑定任务 ID 的子代理/任务进展 |
| `memory/sessions/<sid>/checkpoint.md` | **仅由 checkpoint-writer 子代理维护**的上下文检查点 |

文档约定（`mimocode-docs/guide.md`）：

- 持久规则写在 `MEMORY.md` 的 `## Rules` / `## Architecture decisions`；
- **恢复会话时自动注入**记忆，避免 agent 每次「重新认识」项目；
- 用户说「以后一律…」时，agent **直接改 MEMORY.md**，不必等检查点。

本项目 WArmy 的实践例：全局 MEMORY 中钉死产品名 **WARMY / Workhorse Army / 无限牛马**、端口 **59599**、门禁数字、待办队列——换会话仍按同一口径执行。

### 2.2 召回机制（超出窗口后的「想起来」）

| 手段 | 原理 |
|------|------|
| **memory 检索** | 对 Markdown 正文做 BM25；查询 OR 后按相关度排序；低分噪音丢弃 |
| **升级搜索** | 0 命中**不等于**没记过：先减词 → 直接 `Grep` 记忆目录 → `history` 工具读原始对话/工具输出 |
| **session notes** | 唯一合法草稿本；禁止另建 `learning.md` 等，避免记忆碎片化 |
| **fork 会话** | 把产品主原话 + 工作队列 + 门禁整段注入新会话「冷启动」 |
| **`/dream`** | 扫描近期轨迹，把**耐久知识**晋升进 MEMORY，并清理过期条目（默认约 7 天一轮） |

**技术要点**：记忆是**人类可读 Markdown**，不是黑盒向量库；可版本管理、可手改、可审计。检索是辅助，**权威是文件本身**。

### 2.3 运行时「钉在提示里」的软记忆

每个回合系统会重新注入（本会话可见）：

- 工作目录 / 项目路径；
- 回复语言（zh-CN）；
- 技术注意（Windows 下用 PowerShell、脚本避免内联中文/引号等）；
- Auto-Worktree 规则（主 worktree 并发写前先问用户）；
- session memory 路径与检索提示。

这属于**结构性重复**：不靠模型「自觉记住」，而靠**每回合重申不变量**。

### 2.4 优缺点

| 优点 | 缺点 / 边界 |
|------|-------------|
| 跨会话/跨 fork 可恢复 | MEMORY 过期不清理会误导 |
| 可审计、可手改 | 大量条目会挤占提示预算 |
| 与 git/门禁数字绑定，可验证 | BM25 对同义词弱，需「升级搜索」纪律 |
| 层级清晰（全局/项目/会话/任务） | 双写风险：上下文与 MEMORY 不一致时以谁为准（约定：以门禁/文件事实为准） |

## 三、超出上下文时怎么办

### 3.1 产品文档层（MiMoCode）

- **Auto-checkpoints**：接近上限时由子代理写 `checkpoint.md`；
- **Context reconstruction**：压缩历史后用检查点 + 记忆重建「必要上下文」；
- **Budgeted injection**：注入有预算，不是无限塞全文；
- **Compaction / checkpoint 配置**可在 `mimocode.json` 中调。

### 3.2 本项目（WArmy 产品）同构设计

| MiMo Desktop/引擎 | WArmy 对应 |
|-------------------|------------|
| 上下文压缩 + 指针 | **有界渲染器**：注入恒 ≤ 预算，历史用 `retrieve(seq/recordId)` 解引用 |
| 记忆 JSONL / 检索 | **memory-os**：JSONL 唯一事实 + FTS/向量 + `recall`/`retrieve` 工具 |
| 检查点 | **回退点**（文件层）+ 容器环境固化（环境层，分层不混） |
| 会话日志恢复 | 启动从 `fast-memory.jsonl` **重建 chatLogs** |

设计口号一致：**「上限固定，细节不丢」**。

### 3.3 会话侧「丢上下文」时的工程纪律

1. 先 **MEMORY / notes** 查，不空猜；
2. 读 **ADR / README / 门禁脚本输出** 作事实；
3. fork 时把 **原话口径 + 门禁数字 + 阻塞项** 写进启动指令；
4. 禁止用搜索 API 的 AI 摘要当事实（全局 MEMORY 明文规定）。

## 四、如何确保任务「真实、有序、有效」完成

### 4.1 任务树（task tool）

- ID：`T1`、`T1.1`…；状态机：`open ↔ in_progress`，`→ blocked → open`，`→ done | abandoned`；
- 纪律：**3+ 步就建任务**；开工前 `create` 全套步骤，`start` 后立刻做，`done` 立刻收；
- **UI 侧栏任务列表**与工具状态同步，用户可见「正在干什么」；
- 不许「套件绿就算完」时，产品主人可把标准写进启动指令（如 UI 必须真浏览器看图）。

### 4.2 子代理与绑定进展

- `actor spawn` 后台并行；返回格式固定：

```text
**Status**: success | partial | failed | blocked
**Summary**: ...
**Files touched**: ...
**Findings worth promoting**: ...
```

- 传入 `task_id` 时，结束前必须写 `tasks/<id>/progress.md`，否则结果不被采信；
- 被权限拒绝（如 `external_directory`）→ **记录规则原文后改主会话自己做**，不停摆。

### 4.3 「真完成」的验收哲学（本项目尤其严）

| 做法 | 含义 |
|------|------|
| 门禁脚本数字 | i18n/wiring/probe/router/memory… 必须**真实 PASS 数** |
| 证据等级 | 容器「已固化」必须 commit + **image-inspect 回读**，否则 `refused` |
| fail-loud | 端口绑定失败**禁止静默换端口** |
| 套件绿 ≠ 产品绿 | UI 须真浏览器；e2e 断言要对齐产品定稿（如默认 GitHub 更新源） |
| 变更后读回 | 计划任务等写操作：成功 + **read-back** 才许说「已创建」 |

### 4.4 计划任务（automation）

- `automation_update`：create/update/pause/resume/delete；
- 创建前 **list + 规范化去重**，不重复问用户已给的信息；
- 每次 run 是**独立任务快照**，不继承普通对话上下文（防串味）；
- 提醒类 prompt **不得**擅自改任务配置。

### 4.5 优缺点

| 优点 | 缺点 |
|------|------|
| 步骤可见、可阻塞/恢复 | 任务树过碎会增加管理开销 |
| 子代理进展落盘可审计 | progress.md 与真实代码仍可能脱节，需门禁兜底 |
| 验收偏「可证明」而非「感觉做完了」 | 真机/双机/交互 UI 仍有环境阻塞 |
| 目标判停（`/goal` judge）可选 | 判停模型过松/过严需调 |

## 五、「弹出选项卡让用户选择」如何实现

### 5.1 工具层（Agent 侧）

会话暴露 **`question`** 工具（本会话即如此）：

- 入参：`questions[]`，每项含 `question` / `header` / `options[]`（`label`+`description`）；
- 可选：`multiple`（**多选必须显式 true**，否则桌面单选点一下就提交）、`custom`（「自己填」由系统自动加，勿在 options 里写 Other）；
- 指令约束：**禁止用纯文本列出选项让用户打字**；必须走 `question` 工具，桌面才会渲染**可点选卡片**；
- 返回：选项 **label 数组**，不是自由文本主路径。

### 5.2 桌面渲染层

- Electron 主界面在对话流中插入交互卡片（选项按钮、多选框、自定义输入）；
- 与**权限审批卡**（Allow once / Always allow / Reject）、**消息操作**（fork/复制）同一类「结构化 UI 注入」模式；
- 单选：点击即提交；多选：勾选后提交；避免模型用正文列表「假装」选项。

### 5.3 原理与边界

| 维度 | 说明 |
|------|------|
| **原理** | 模型输出的是**工具调用 JSON**，宿主解析后渲染；用户选择以**结构化结果**回到下一轮模型输入 |
| **目的** | 降低自由文本歧义、保证可统计、可埋点、可无障碍 |
| **边界** | 仅宿主支持的 UI 类型；自定义项系统自动提供；不能发明宿主不认识的控件 |
| **失败模式** | 模型不用工具只写列表 → 桌面无法点选（故系统强调 MUST use tool） |
| **与 WARMY 权限卡对比** | WArmy 是「工具调用审批」；MiMo question 是「信息收集/决策」——同属结构化交互，语义不同 |

### 5.4 其他结构化交互

- **权限卡**：写文件/跑命令前确认；Full access 才自动通过；
- **Inline comment / fork**：选中回复片段带上下文开分支会话；
- **present_files**：交付物卡片，首文件自动预览；
- **sci-widget**：交互演示嵌在对话里（解释用，不是产品交付页）。

## 六、其他值得吸收的好设计

1. **Skill 即文档 + 显式触发**  
   高置信自动加载；`/skill` 或明确点名；减少「模型猜工具」。

2. **文件化 Agent / 自定义命令**  
   `.mimocode/agent/*.md`、`command/*.md`：Markdown 正文即 system prompt，热更新，零改引擎。

3. **配置分层**  
   项目 `.mimocode/mimocode.json` 覆盖全局；schema 校验；密钥脱敏后再输出。

4. **主 worktree 并发保护**  
   同仓库多写手时提示是否用隔离 worktree——避免互相覆盖。

5. **引用规范**  
   代码引用 `file_path:line_number`，便于跳转与审计。

6. **诚实失败与「环境缺 X」**  
   工具链不在 PATH 时先按 Windows 方式找，**验证过再声称缺失**。

7. **计费/权限/会话隔离**  
   计划任务、子代理、主对话权限边界清晰，避免子进程「继承」不该有的写权限。

8. **产品内本地优先**  
   与 WArmy 相同价值观：数据默认在本机、可观测、可导出。

## 七、可复用到 **WArmy（无限牛马）** 的设计

WArmy 已具备：有界上下文、memory-os、队列落盘、容器诚实语义、项目级文件台账、10 语言等。
下列是 **MiMo Desktop 模式** 对 WARMY 的直接映射。

### 7.1 项目级「MEMORY」——牛马项目记忆

| MiMo | WArmy 建议 |
|------|------------|
| 项目 MEMORY.md + Rules | 每个**项目群**增加 `project-memory.md`（或 group store 字段）：目标、门禁、端口、禁止项 |
| 恢复注入 | 项目启动/值班选卡时把「项目记忆」片段注入状态卡片（有界） |
| /dream | 「整理项目记忆」工具：从看板+台账+对话摘要晋升耐久规则 |

**收益**：换机器成员、值班轮换时，**项目规矩不丢**。

### 7.2 任务树 + progress（成员可见）

| MiMo | WArmy 建议 |
|------|------------|
| `task` T1/T1.1 + UI 列表 | 项目右栏「任务」与看板对齐；子任务可 block/done |
| tasks/*/progress.md | 已有**文件访问台账**可扩展：`duty` 执行摘要写入项目级 progress（成员可见） |
| Status/Summary 格式 | 值班回复固定字段：结论 / 证据 / 门禁数字 / 待用户项 |

### 7.3 选项卡：创建项目 / 容器 / 端口 / 安全模式

WArmy 已有权限卡；可增加 **question 型 IPC**：

```text
创建项目
  □ 开发环境：本机 | 容器（安全隔离）
  □ 运行时：Docker / Podman / WSL（探测结果）
端口冲突
  ○ 59599（当前）  ○ 52555  ○ 55151 …（真 bind 建议，只填入不自动改）
安全模式
  ○ 常规 / 严格 / 完全
```

实现要点（与 MiMo 同构）：

- 渲染层 **JSON Schema → 卡片**，用户点选回 IPC；
- **禁止**只写正文列表；
- 多选显式 `multiple`；
- 结果写入 group/settings 并 **read-back**。

### 7.4 上下文：对齐「检查点 + 记忆注入」

- 值班状态卡片已类似 StatusCard；可增加：**项目记忆摘要 + 最近门禁失败**；
- 长项目：定期写「项目检查点」（目标、未完成、环境指纹），与回退点分层对应。

### 7.5 Goal 判停（项目任务）

- 项目任务声明验收条件（如「i18n 键集相等且 UI 无 key 泄漏」）；
- 完成前用**本地脚本/子代理判官**跑门禁，**判停模型不通过则继续**；
- 与「真实有序有效」一致：**可证明才算完**。

### 7.6 记忆纪律写进产品

- 项目笔记仅一个入口（如「项目纪要」），禁止多处碎片；
- 全局偏好（语言、供应商）与**项目规则**分离存储；
- 检索：关键词 FTS（已有）+「找不到就翻原始台账/日志」的产品内指引。

### 7.7 计划任务 / 提醒

- WArmy SMTP/邮件提醒已有雏形；可做**项目级自动化**：值班每日摘要、门禁红了通知；
- 创建前 list 去重 + 配置快照（MiMo automation 同款纪律）。

### 7.8 Skill 面板 → 项目工具箱

- 已实现 Skill 管理 UI；可对齐：**项目可发现 skill 与成员可见说明**、暂停=不进入工具注册表；
- 文档写清：自动发现目录删除**置灰**（已做）与暂停语义。

### 7.9 不建议照搬的部分

| MiMo 特性 | WArmy 理由 |
|-----------|------------|
| 完整 coding-agent IDE 职责 | WArmy 定位是**项目指挥台**，不是 IDE 插件 |
| 自动继承 Claude/skills 多品牌根 | 产品需可控工具面；仅 MiMoCode 根加载更安全 |
| Vivid 动效/桌宠等 | 与牛马产品气质无关，非核心 |
| 把一切塞进 system prompt | 应坚持 **有界注入 + 工具解引用** |

## 九、结论（可执行摘要）

1. **记得住**：多层 Markdown 记忆 + 恢复时注入 + 每回合不变量重申 + 可检索升级路径。  
2. **撑得住上下文**：检查点/压缩/预算注入；WArmy 用有界渲染 + 可解引用记忆同构。  
3. **做得完**：任务树可见、进展落盘、门禁数字、禁止假成功、变更后读回。  
4. **问得清**：结构化选项卡（工具 JSON → 桌面渲染），禁止纯文本假选项。  
5. **WArmy 优先复用**：项目 MEMORY、任务树+progress、决策选项卡、门禁判停、自动化去重——与现有 memory-os / 看板 / 队列 / 容器诚实语义**互补**，不必重造引擎。
