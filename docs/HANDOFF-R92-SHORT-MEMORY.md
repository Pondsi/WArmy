# 第 92 轮交接 · 短记忆（原「规范」）

> 用户口径：第四列不再显示规范卡片、添加卡片里也没有；**规范更名为短记忆**；功能仍在（继续注入），
> 但**只由归档时的模型更新**，人看不到也改不了。

## 1. 做了什么

- **界面移除**：
  - `index.html` 删除 `#mianBanGuiFanKuai`（原规范卡）。
  - `renderer/app.js` 删除 `renderPanelGuiFan` 与相关 IPC 调用；`PAN_DEFAULT` / `PAN_ALL` / 添加卡片下拉都不再有规范卡。
  - `preload.cjs` 删除 `guiFanDu/guiFanShe`；主进程删除对应 IPC。**模型/界面都没有读写入口**。
- **一次性迁移**：老配置 `panCards` 里若有 `mianBanGuiFanKuai`，读取时换成新的「要求」卡；只在旧数组确实含规范卡时替换一次，用户后来删掉要求卡不会被强行加回。
- **改名**：
  - 注入段标题改为 `【短记忆 · 只作用于本会话（归档自动维护）】`。
  - 压缩层名从 `规范` 改为 `短记忆`；`TI_SHI_SHANG_XIAN` 同时保留旧名 `规范` 作为兼容别名（同 2000 字）。
  - 注释、归档提示、印象/教条/束缚/认知里的优先级说明全部改为「要求 > 短记忆」。
- **归档更新**（第 93 轮改口径，见 `HANDOFF-R93-SHORT-MEMORY-FREQ.md`）：
  - `guiNaGuiFan` → `guiNaDuanJiYi`；**不再只限项目/群聊**，所有会话都更新。
  - 第 93 轮起：只从**本会话有权读的知识层**挑 `useCount>0` 且不在短记忆里的条目（按使用次数降序，最多 10 条）；低于上限时整份超过 2000 字则**按使用频率从低到高**丢，不再按最旧。
  - 归档提示同时带上用户「要求」（只读）和本会话短记忆（按它归置；短记忆由宿主按知识库使用频率更新）。
- **读写边界**：
  - `duGuiFan` 仍读 `userData/guifan/<sid>.md`；读时用 `yaSuoYiCeng({ceng:'短记忆'})` 自愈压缩（发出去的和文件里的是同一份）。
  - 没有用户 IPC、没有模型工具；文件在 userData，工作区沙箱默认够不到。

## 2. 为什么保留 `guifan/` 目录

历史配置里已经有这些文件；改名目录会丢内容。对外一律叫「短记忆」，内部路径保持兼容。

## 3. 注入位置

`术 → 要求 → 短记忆 → 印象 → 工具 → 教条 → 束缚 → 认知 → 身份/模型/时间`

- 与要求冲突：以要求为准。
- 与术/道/硬门禁冲突：以它们为准。
- 压缩：第 3 层，层内顺序 `短记忆 → 要求 → 术`（短记忆最先让路）。

## 5. 已知取舍 / 最坏情况

- 用户**无法直接纠正**模型归纳错的短记忆（按你的口径“人看不到、不能改”）；只能等下一次归档，或删会话重建。
- 归档只追加“像规矩”的短句，不会把整段对话写进去；宁少勿滥。
- 旧文件里历史用户手写的内容保留并继续注入；程序不再改它（除非超限压缩）。
