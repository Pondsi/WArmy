# 难易 / 杂简 双维分诊（第 98 轮追加，2026-10-27）

> **第 99 轮更新**：难易、杂简、急缓各扩为 1–5 五档（很难…极易、很杂…极简、很急…极缓）；
> 急缓也参与项目执行者的模型/思考偏好；思考档位改为模型实际档位百分比映射。以
> [`HANDOFF-R99.md`](./HANDOFF-R99.md) 为准；本文保留第 98 轮双维记录。

> 用户口径：
> “难易度进行一个更细的拆分。分为：**难易**和**杂简**。单步计算困难的叫难的（反之为易），
> 步骤杂（多任务或拆分多任务后，各任务之间关系复杂，互相关联度多而深；
> 或者单任务无法完成，但拆分为多任务又有难度的情况）的为杂（反之为简）。
> 难的任务交给更智能的模型，杂的任务要使用更高的思考级别。
> 如果已经是最智能的模型、但仍然可能无法解决问题，就可以提高思考级别来确保任务完成度，
> 即使这个任务并不杂而是简的，也可以提高思考级别。
> 一个任务可以有：难杂急、难杂缓、难简急、难简缓、易杂急、易杂缓、易简急、易简缓。
> 要根据实际情况合理安排。”

---

## 一、两个维度，不是一件事

| 维度 | 含义 | 影响 | 不影响 |
|---|---|---|---|
| **难 / 易** | 单步计算/推理本身有多难；一步就能做完但这一步很难，也算难 | **模型档**：难→high、中→mid、易→low | 步骤排队/插话 |
| **杂 / 简** | 步骤多、要拆分、子任务之间关联多而深；单任务做不完、拆开又难协调，也算杂 | **思考级别**：杂→high；中→medium；简→low/off | 模型档（模型只由难易决定） |
| **急 / 缓** | P0/P1=急，P2/P3=缓 | 投递/插队/排队/插话方式 | 模型档、思考级别 |

> 3 分在八组合里归入“易/简”一侧；但 3 分仍会得到 **mid 模型 / medium 思考**，不是无成本。

---

## 二、八种组合

| 组合 | 模型档 | 思考档 | 投递/插话 |
|---|---|---|---|
| **难杂急** | high | high | 急：P0 停止 / P1 加急 |
| **难杂缓** | high | high | 缓：P2 插入 / P3 排队 |
| **难简急** | high | 至少 medium；nan≥5/低置信/高风险→high | 急 |
| **难简缓** | high | 至少 medium；nan≥5/低置信/高风险→high | 缓 |
| **易杂急** | low/mid | high | 急 |
| **易杂缓** | low/mid | high | 缓 |
| **易简急** | low | low/off | 急 |
| **易简缓** | low | low/off | 缓 |

### 例子

- **难杂急**：生产环境发布，要拆成迁移、回滚、验证三条互相依赖的流水线，且要立刻做。
  → 最强模型 + 最高思考；P0/P1 投递。
- **难杂缓**：同一件事但不着急。→ 最强模型 + 最高思考；P2/P3 投递。
- **难简急**：一句“证明这个 NP 完全性”，步骤很少但单步极难。→ 最强模型；思考至少 medium，
  若置信低/风险高则 high；急投递。
- **难简缓**：同上但不急。→ 最强模型 + medium/high 思考；正常投递。
- **易杂急**：把 30 个小文件按同一规则改名，步骤多但每步都简单。→ 低/中模型 + 高思考；急投递。
- **易杂缓**：同上不急。→ 低/中模型 + 高思考；正常投递。
- **易简急**：一句“现在几点”。→ 低模型 + 关思考；急投递（加急/插入）。
- **易简缓**：一句“你好”。→ 低模型 + 关思考；正常投递。

## 三、决策规则（代码实际执行）

### 1. 模型档只看 nan

- `nan ≥ 4` ⇒ `high`（难）
- `nan = 3` ⇒ `mid`（中）
- `nan ≤ 2` ⇒ `low`（易）

`za` 不改变模型档。所以“易杂”会用较低模型 + 高思考；“难简”会用高模型 + 中/高思考。

### 2. 思考档先看 za

- `za ≥ 4` ⇒ `high`
- `za = 3` ⇒ `medium`
- `za = 2` ⇒ `low`
- `za ≤ 1` ⇒ `off`

### 3. 顶模型仍可能失手时，简任务也抬思考

满足任一条，思考至少 `high`：

- `nan ≥ 5`（单步极难）
- `nan ≥ 4` 且 `confidence < 0.6`（分类器/启发式没把握）
- `nan ≥ 4` 且 `importance ≥ 4`（高重要/高风险）

难任务（`nan ≥ 4`）思考至少 `medium`，所以不会出现“用最强模型但完全不思考”。

### 4. 急/缓不影响模型和思考

`P0/P1` 与 `P2/P3` 只改变八组合的后缀和投递方式；同一 nan/za 下，急与缓的
`modelTier`、`thinkLevel` 必须完全相同（门禁有硬断言）。

## 四、分类器

### 模型分诊

`panDuanZhongYaoFuZa(content, urgency)` 输出：

```json
{"nan":1-5,"za":1-5,"importance":1-5,"confidence":0-1,"reason":"一句话"}
```

提示词明确要求：

- `nan` 是单步难度，**不要把步骤多当成难**；
- `za` 是步骤/关联复杂度，**不要把单步难当成杂**；
- `急/缓`只影响投递，**不要算进 nan/za/importance**。

模型结果再走 `panDuanNanZa` 统一折算 modelTier/thinkLevel/combo，避免模型直接给不一致的档位。

### 本地启发式（分类模型不可用）

`guSuanZhongYaoFuZa(content, urgency)`：

- **nan**：专业计算/深度推理词（证明/算法/架构/根因/数学/安全/合同…）+ 高风险 + 长难题 + “高难/专家/不能出错”。
  高风险加 2（不可逆/高代价的判断本身要更深）。
- **za**：长度、步骤词（先/再/最后/分别/多步/分步/逐个…）、工具使用、拆分/依赖/并行/汇总/互相关联。
- `importance`：工具使用 + 高风险。
- 置信度：高风险 0.9；多步/关联 0.7；其余 0.6。

## 七、边界与例子

1. **3 分不是无成本**：nan=3 得 mid 模型，za=3 得 medium 思考；只是八组合里归到“易/简”。
2. **高风险 ≠ 一定难**：高风险会把 nan 抬高（不可逆判断需要更深），但不直接决定 za；
   例如“删除一个文件”可能 nan 高、za 低 ⇒ 高模型 + 中/高思考，而不是“杂”。
3. **多任务 ≠ 一定难**：30 个简单重命名是易杂；模型可以低，但思考要高。
4. **顶模型提升是条件性的**：nan=4、置信 0.8、importance 3、za=1 时思考 medium，不强制 high；
   只有 nan≥5 / 低置信 / 高重要才抬到 high。
5. **急/缓绝不改模型/思考**：门禁有对照断言；如果看到“加急就换强模型”，那是 bug。
6. **模型仍由牛马设置决定**：值班者只提供 nan/za 和由此折算的 modelTier/thinkLevel，
   不能直接写模型；执行者自己勾了智能模式才按 modelTier 在它自己的链上挑。
