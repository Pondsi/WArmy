## 2. 用户问题的直接回答

### 赞/踩有什么用
不是训练模型，也不立即改本轮回答。它归档为“印象提取”的素材（`state.votes` 按消息指纹），归档时与最近对话一起交给整理模型归纳“用户喜欢/不喜欢什么”，并写 `smart-config.user-vote` 审计。最坏情况：赞踩只影响长期“印象”，整理模型归纳错时仍需人在印象卡里改；它不会改变当时的回复。

### 8K/4K 能放多少字
预算 = 整条请求，含系统提示、工具定义、历史与输出预留；下表是**扣掉固定开销后的正文粗略上限**（不同 tokenizer 差 10–25%）：

| 语言 | 8K token 约 | 4K token 约 | 口径 |
|---|---|---|---|
| 中文 | 4,000–7,500 字 | 2,000–3,700 字 | 约 1–1.5 token/字 |
| 英文 | 5,500–6,500 单词 | 2,700–3,200 单词 | 约 1.3 token/单词 |
| 日文 | 4,000–7,000 字 | 2,000–3,500 字 | 约 1–1.5 token/字 |
| 韩文 | 3,500–5,500 字 | 1,700–2,700 字 | 约 1.5–2 token/字 |
| 法文 | 5,000–6,000 单词 | 2,500–3,000 单词 | 约 1.5 token/单词 |

最坏情况：把 8K 全用来放正文，模型没有余量生成回答；实际要再留 20–30%。

### 微信扫码确认很晚才显示成功
真因是扫码确认后 `ILinkAdapter.lianJie()` 同步等待官方 `getupdates` 长轮询（最长 45s）才返回。现在首连只做 4 秒探活，超时不写“连接失败”，真正长轮询交给后台；确认后界面立即亮“已连接”，随后由后台校验。若仍慢，是腾讯官方确认/灰度或网络，不是本地主线程被长轮询卡死。

### 授权卡出现时执行中内容消失
根因是授权卡在聊天区下方占位挤压视口，旧滚动位置不再处于底部，看起来像流式块消失。现在卡片渲染前记录是否在底部，渲染后 rAF 重绘流式块 + 按最终规则归组 + 保持底部。本轮时序改造后仍由 `verify-r48-zhongjian-ui` 覆盖。

### 执行过程为什么有时工具全在最后
旧代码只在“思考/中间回复分段 ≥2”时才按 ts 穿插，只有一段时工具行全部 append 到末尾。现在无论几段都按 ts 插入；没有分段才按时间顺序列出。流式也使用同一套 `guiNaXingDong`，中间回复进时间线而不是消失。

### 模型能力标签怎么判断 / 更优方案
顺序：Ollama `/api/show` 的 `capabilities`（如 `decision,vision`、`completion,tools,thinking`）→ 人工核对过的已知表 → 型号名兜底（带 `orcarouter` 负向断言）；`family=unknown` 且实测加载失败的模型一律 `unknown+buKeYong`，不进任何链。更优方案是端点元数据优先 + 设置页允许用户手动覆盖 kind（可审计），并把覆盖结果随模型配置落盘；这样新模型不必等程序更新。

### 第四列的规范/印象/项目记忆是什么
- 规范：只作用于当前项目会话的提示词层，每轮注入，优先级在术之后；不是全局道/术。
- 印象：对用户的长期理解（会话级优先、全局兜底），每轮注入，归档时更新；可能错，用户可改/否认。
- 项目记忆：项目目标/规矩，只在项目内注入；与“我的牛马”单聊无关。
三张卡都有实际注入；不是摆设。第四列只是编辑/查看入口，不另存一份提示词。

### 知识库搜索后删除/重写是否解决脱敏
只解决“发现后的补救”，不解决“注入前的预防”。删除/重写适合清理旧条目；剩余边界是私密/社交图谱/白名单/分级。两者要一起用。最坏情况：只做事后删除，旧条目在清理前已被注入过一次。

### `round_end · cow` 回退点卡
它是自动收尾打的 `round_end` 回退点，`cow` 是 copy-on-write 策略；本轮已从卡片隐藏，只显示可用的轮次起点。它不是新功能，也不会自动回档。

### “停止并回退”与“回到这一轮之前”
- 回档：停止当前 AI/工具，恢复所有本程序记录到的文件改动；聊天记录保留，并写入“回档到…”。
- 旧的“回到这一轮之前”：会删聊天记录并截断到某一轮；本轮已按用户要求**删除按钮/功能**。

### `dimavz/whisper-tiny` 是什么
Ollama 上的 GGUF 文本模型（whisper.cpp 转换），`family=unknown`，实测加载失败；**不是可用 ASR**。它被旧名字规则误塞进对话/听话链。现在能力表标 unknown+不可用，ASR 链与 UI 都排除。
